# CatForge SKU brain

The schema extends the official `gbrain-base-v2` pack. `schema/contract.json` specifies scoped natural keys and the outgoing cardinality of the project edges. A source page identifies a versioned evidence record. A snapshot identifies immutable selected inputs, including the versions with no matching rows. Use the same project/category scope at both ends of an edge.

- A parameter definition specifies the value type and canonical unit. A SKU parameter carries the selected value, original value, unit, presence, quality flags, confidence, and evidence identifiers. Explicit false, unavailable and conflicting observations remain distinguishable.
- SKU claims preserve original text, claim code, parameter support and source rule. A comment atom is a sentence-level judgment with topic, polarity and support/contradiction codes. Market observations preserve window, period, channel grain and amounts. A cohort specifies members, purpose and the overlap policy.
- A SKU profile contains all candidate assessments. Assessments carry role, components, score, confidence, evidence, review state and input revision. An allocation includes its denominator and unallocated balance. Price/volume comparisons are observational. Competitor pairs are directional.
- Example path: SKU ← observed_for — parameter observation → measures → parameter. A primary battlefield assessment points to the same SKU and to the shared battlefield, and references its fact inputs. Traverse incoming assesses_dimension edges for reverse lookup.
- The anatomy of a stored page is a GBrain type, a stable slug and typed JSON data. Strong key/endpoint contracts belong to the writer. Install the pack under the selected brain home in `.gbrain/schema-packs/catforge-sku/pack.yaml`; `gbrain schema validate catforge-sku` and `gbrain schema lint catforge-sku` verify it. `GBRAIN_SCHEMA_PACK=catforge-sku` scopes a local command. A project MCP memory-writer's read/write scopes allow pages and links; schema activation on its server is a separate operation. Sample records and connection details stay in the authorized project environment.

After freezing all three positioning results, run `position_graph.py SNAPSHOT RESULTS STAGE` with the verified readback and an empty private staging directory. Import the staged pages into the same isolated brain and extract frontmatter links. A candidate links to its SKU, definition, matched parameters, comment evidence, market window and comparison pools. Record any absent sources from its score breakdown.

An optional `--goal FILE` adds a separate PM objective. Supply the SKU, stable goal ID, revision, owner, source reference, objective, validity dates, battlefield code and taxonomy version. Issue a new revision when the priority changes. Scoring takes no goal input. The held-out comparison checks candidate scalar fields and nested breakdowns, and reports evidence-order and displayed-example differences separately.
