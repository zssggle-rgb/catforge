## 3. Goal 与定时器统一合同

### 3.1 Goal 启动

每个 Goal 启动时必须：

1. 确认不存在其他 active Goal；
2. 调用 create_goal，objective 只包含当前 Goal；
3. 写入当前 Goal 的允许修改路径、禁止事项和验收门禁；
4. 创建名为 sellpoint-value-v4-Gxx-heartbeat 的 10 分钟周期定时器；
5. 将定时器 ID 写入 Goal 进度记录。

不设置 token budget，除非用户另行明确要求。

### 3.2 定时器职责

每次定时器唤醒只做以下事情：

1. 读取唯一 active Goal；
2. 读取当前 Goal 进度、工作区状态和最近测试结果；
3. 只推进当前 Goal 的下一个未完成门禁；
4. 更新进度记录；
5. Goal 已完成时停止并删除当前定时器；
6. 同一阻塞连续出现三次且无法继续时，记录证据、停止定时器并将 Goal 标记 blocked；
7. 用户发出停止指令时立即停止当前工作和定时器。

定时器禁止：

- 偷做下一 Goal；
- 一次创建多个 Goal；
- 因为时间到了而降低验收标准；
- 在失败时静默修改前序冻结合同；
- 自动触发部署、路由切换或其他扩大权限的动作。

### 3.3 Goal 关闭

每个 Goal 必须生成：

    docs/core3_mvp/real_data_v2/current_implementation/sellpoint_value_pm_v4/
      Gxx_progress.md
      Gxx_closure_receipt.md
      Gxx_artifact_manifest.json

关闭回执至少记录：

- objective；
- 前置 Goal 和输入 hash；
- 实际修改文件；
- 数据来源和版本；
- 测试命令及结果；
- 业务、方法、工程门禁；
- 已知限制；
- commit SHA；
- 下一 Goal 是否准入。

完成后：

1. 精确暂存当前 Goal 产生的文件；
2. 提交独立 commit；
3. 删除当前定时器；
4. 调用 update_goal(status=complete)；
5. 用户已批准整条任务链且下一 Goal 前置条件满足时，自动创建下一 Goal；G09 完成后例外，必须等待 G10 的单独上线授权。

### 3.4 修复 Goal

后续发现前序 Goal 的冻结合同错误时：

- 停止主链；
- 创建 Gxx-R1 修复 Goal；
- 只修复前序合同和受影响实现；
- 重跑所有受影响下游门禁；
- 不在当前 Goal 静默篡改历史结果。

## 11. G05：卖点级反事实与识别门禁

目标：为每个可量化卖点组合构造可信的基础、同价值和上探对照。

实现范围：

- 战场、尺寸、时间、平台/渠道市场单元；
- 价值强度业务档位；
- 基础价值对照池；
- 同价值直接竞品池；
- 上探标杆池；
- 共同在售、价格重叠、配置差异、品牌、促销和库存审计；
- counterfactual quality grade；
- 不可识别原因。

关键断言：

- 同价值竞品只回答选择反事实；

- 单一差异很大的 SKU pair 不进入卖点 WTP；

- 不能用目标结果反推战场归属；
- M12C 旧金额不参与对照选择。

## 12. G06：选择贡献与市场隐含 WTP

目标：在识别门槛通过的反事实池上估计选择贡献和市场隐含 WTP。

实现顺序：

1. 高可比匹配对照基线；
2. 多 SKU 市场选择模型；
3. 价格和价值强度敏感性分析；
4. WTP 区间和方法等级；
5. 不可识别降级。

必须输出：

- 同价选择差异；
- 价值强度档位变化对应的选择变化；
- 价格系数和方向检查；
- 市场隐含 WTP 中位或区间；
- 适用战场、尺寸、渠道和窗口；
- 样本和重叠范围；
- 方法等级、主要混杂和敏感性结果。

禁止：

- 整机价差按卖点评分分摊；
- 使用 M12C 旧金额作为监督标签；
- 外推到未观察价格或价值档位；
- 价格系数方向异常时输出金额；
- 把组合 WTP 拆给完全共线技术；
- 把市场隐含 WTP 写成真实心理最高价。

测试至少覆盖：

- 已知合成数据参数恢复；
- 价格系数负向；
- 完全共线；
- 无价格变化；
- 促销污染；
- 品牌和时间固定效应；
- 匹配池边界；
- 样本不足；
- 不同模型方向一致和不一致。

## 19. 工程计划审查结论

### What already exists

- M11C：复用价值战场画像；
- M11D：复用战场市场空间和 SKU 量价贡献；
- M12D：复用采购理由和价值锚点；
- M07/M01：复用周度市场事实；
- M12C：仅复用可比池和档位中间事实，不复用最终金额；
- V2：保留运行和回归，不复用其卖点金额或固定动作；
- analyst 目标解析、CLI、报告发布：优先抽取复用，禁止复制。

### Scope challenge

最小完整范围是四项新增能力：

1. 采购理由、用户价值和卖点组合连接；
2. 卖点级三类反事实；
3. 选择贡献和市场隐含 WTP；
4. 产品经理统一结果。

战场、市场空间、采购理由和实验平台均不新建。

### Architecture

- 采用只读 analyst 层，避免写入和迁移；
- 使用上游发布资产，不平行生产相同事实；
- 量化模型与渲染分离，业务 DTO 是唯一发布入口；
- 模型失败是合法降级，不允许伪金额。

### Code quality

- G02 先冻结最少文件和服务边界；
- 公共逻辑用纯函数；
- 不复制 V2 大型服务；
- 内部字段与中文业务语义分层；
- 每个 Goal 小提交并可回滚。

### Tests

- 测试覆盖图已定义；
- 合成数据验证模型参数；
- 真实 fixture 验证业务边界；
- V2 和上游模块回归不可省略；
- 飞书回读属于 205 集成验收。

### Performance

- 上下文一次批量读取；
- 不逐 SKU/评论 N+1；
- 市场模型按战场和市场窗口批量构造；
- cohort 和模型输入可缓存到本次运行内存；
- G02 冻结性能预算，G08/G09 实测。

### NOT in scope

- 购买前用户心智；
- 实验 WTP 平台；
- 成本和利润；
- 自动产品动作；
- 上游战场/采购理由重建；
- 多品类规则泛化；
- 默认路由立即切换。
