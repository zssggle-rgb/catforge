# 用户卖点价值分析 V4 需求说明

状态：待用户评审，未授权实现
日期：2026-07-11
适用仓库：CatForge
实现原则：与现有产品经理版 V2、旧 V3 候选稿平行，不修改其运行契约

## 1. 产品问题

用户输入一个 SKU、型号或可唯一解析的产品名称，系统回答：

> 这款 SKU 在哪些价值战场中竞争，靠什么采购理由成交，用户实际获得了什么价值，哪些卖点或能力组合共同创造了这项价值；相对于基础价值方案和同价值竞品，本品增加了多少用户价值、市场选择和价格承接，当前能够量化到哪一层？

该功能是单一问题、单一答案的只读分析能力，不建设审批、任务管理、产品经理工作流或生产数据写回。

## 2. 核心业务价值

产品经理已经知道自己为 SKU 配置了什么能力，也能够提出产品希望创造的价值。当前缺少的是一份连接产品投入、用户获得和市场兑现的统一结果：

    价值战场
      -> SKU 采购理由
      -> 用户实际获得的价值
      -> 支撑该价值的卖点与能力组合
      -> 基础价值 / 同价值竞品 / 上探标杆
      -> 相对体验与选择变化
      -> 市场隐含 WTP

该功能的核心价值是把现有 M11C、M11D、M12D、产品事实、用户体验和市场量价连接起来，明确：

1. 什么只是产品配置；
2. 什么已经形成用户实际获得的价值；
3. 什么是行业门槛，什么是本品相对增量；
4. 什么已经反映为市场选择；
5. 什么能够被市场价格承接；
6. 当前量化结果是体验差异、选择关联、整机价差，还是可识别的卖点组合市场隐含 WTP。

## 3. 关键概念与关系

### 3.1 价值战场

价值战场是用户围绕相同任务、客群、价格环境和核心价值比较产品的市场空间。V4 直接消费 M11C/M11D 的已发布结果，不重新生成战场或分配市场空间。

### 3.2 SKU 采购理由

SKU 采购理由是 M12D 已发布的核心支付理由、辅助理由、弱表达和风险锚点。V4 不重新生产购买理由，只保留其证据强度、来源和是否为直接用户表达或多源推导结果。

### 3.3 用户实际获得的价值

用户实际获得的价值来自当前已有评论和体验事实，表达用户使用产品后获得的具体结果或好处。它不能由产品宣传直接推断，也不能要求用户说出技术名称。

例如：

- 产品能力：高亮、分区控光、MiniLED；
- 用户结果：强光环境仍然看得清、暗场层次更完整、字幕周围光晕更少；
- 用户价值：不同光线环境下能够更轻松地观看。

原始证据只支持“画面清晰”时，结果必须停在基础清晰体验，不能补写强光、暗场或光晕场景。

### 3.4 卖点与能力组合

卖点是产品侧能力、参数或价值表达。卖点不是用户价值本身，而是用户价值的产品侧来源。

默认以卖点组合为量化对象：

    高亮 + 分区控光 + MiniLED + 画质处理
      -> 强光清晰与明暗层次
      -> 高端画质升级采购理由

只有在市场中存在足够独立变化或可控对照时，才允许把组合拆成单项卖点量化。

### 3.5 选择反事实与价值反事实

必须区分两类反事实：

| 类型 | 对照对象 | 回答的问题 |
| --- | --- | --- |
| 选择反事实 | 提供类似用户价值的直接竞品 | 用户在相似价值方案中选择谁，本品整套方案能承受多少相对价差 |
| 价值反事实 | 不具备、较弱或处于基础档的价值方案 | 从基础价值升级后，用户体验、选择和可接受价格增加多少 |

同价值竞品不能单独证明该价值本身的增量 WTP；基础价值对照不能自动证明本品相对同价值竞品实现得更好。

### 3.6 市场隐含 WTP

V4 当前只允许估计市场隐含 WTP：

> 在既有市场选择中，目标价值组合相对于基础价值方案，对选择效用的增量与价格敏感度之比。

简化表达：

    市场隐含 WTP
      = - 价值组合选择效用系数 / 价格选择效用系数

该结果属于基于历史市场行为和模型假设的估计，不得表述为用户真实心理最高价，也不得与实验 WTP 混写。

## 4. 当前数据边界

### 4.1 当前允许使用

| 数据 | 来源 | V4 用途 |
| --- | --- | --- |
| SKU 产品事实 | M03B/M04C | 确认产品能力、参数档位、卖点事实和冲突 |
| 用户实际体验 | M05C 及已清洗评论事实 | 判断购买后用户实际获得的价值、正负结果和具体度 |
| 市场量价 | M07/M01 周度事实 | 构造真实净价、销量、销额、共同在售周和渠道市场单元 |
| 用户任务与客群 | M09C/M10C | 解释价值适用的任务和客群，不冒充购买前直接心智 |
| 价值战场画像 | M11C | 获取主、辅、机会、拖累战场和各证据分项 |
| 战场市场空间 | M11D | 获取战场规模、SKU 构成、量价分配和市场窗口 |
| SKU 采购理由 | M12D | 获取价值主题、采购理由、关键价值锚点和证据强度 |
| 现有可比池与档位规则 | M12C 中间结果或规则 | 复用候选池、参数档位和事实，不消费最终分摊金额作为 WTP |
| 竞品集合与角色 | M14 或已发布竞品分析 | 确定同价值直接竞品和上探标杆，不在 V4 重选竞品 |

### 4.2 当前不使用

当前没有的数据不进入 V4 主合同：

- 广告曝光、详情页点击和停留；
- 搜索关键词和加购对比轨迹；
- 导购咨询、流失和未购买原因；
- 购买前用户访谈或传播 A/B；
- 随机价格实验、联合分析或实验 WTP；
- 增量 BOM、渠道成本、促销成本和利润。

因此 V4 不输出“用户看到宣传后认为产品是什么样”，也不构造购买前价值心智或预期兑现差。

M12D 的采购理由可以作为当前已发布业务资产使用，但必须显示证据强度；不得把多源推导结果改写为“用户购买前明确说”。

## 5. 现有能力复用与新增边界

### 5.1 已有能力，禁止重建

| 已有能力 | 负责模块 | V4 使用方式 |
| --- | --- | --- |
| SKU 价值战场归属 | M11C | 只读消费 |
| 战场市场空间、SKU 量价贡献 | M11D | 只读消费；保留其解释性分配边界 |
| SKU 采购理由和价值锚点 | M12D | 只读消费；保留直接证据与推导证据差异 |
| 产品、评论和市场事实 | M03B/M04C/M05C/M07 | 按权威批次读取 |
| 竞品角色 | M14/竞品分析 | 只读消费，不重新选竞品 |
| M12C 可比池和参数档位 | M12C | 可复用中间事实和规则，不复用最终金额作为 WTP |

### 5.2 V4 真正新增

1. 将 M12D 采购理由连接到用户实际获得的价值；
2. 将用户价值连接到一个或多个卖点与能力组合；
3. 在 M11C/M11D 战场内构造基础价值对照、同价值竞品和上探标杆；
4. 计算相对用户体验结果；
5. 条件满足时估计卖点组合的选择贡献；
6. 条件满足时估计卖点组合的市场隐含 WTP；
7. 将已有战场、采购理由和新增量化整合成产品经理可读的 SKU 产品价值结构。

## 6. 功能需求

### F01 目标 SKU 与权威来源

- 输入支持 SKU、型号和可唯一解析的产品名称；
- 型号和 SKU 必须解析到同一目标；
- 分别锁定 M03B、M04C、M05C、M07、M09C、M10C、M11C、M11D、M12D 的权威版本；
- 多个 current 无法唯一解析时，受影响层返回冲突，不按更新时间静默选择；
- 所有输出保留 category_code、project_id、batch、version、market_window 和 evidence refs。

### F02 产品价值结构

以“价值战场 + 采购理由”为主分析行，而不是以单个技术卖点为主行。

每个主/辅价值战场至少输出：

- 战场名称和市场空间；
- 目标 SKU 在战场中的量价位置；
- M12D 核心或辅助采购理由；
- 用户实际获得的价值；
- 支撑该价值的卖点与能力组合；
- 产品角色；
- 量化状态。

机会、厂家主张和拖累战场不进入正向核心价值汇总，但可在风险或证据不足区域展示。

### F03 采购理由到用户价值连接

每个 M12D 采购理由必须连接：

- 一个或多个标准价值主题；
- 一个或多个用户实际体验结果；
- 体验结果的正向、负向、混合或未知状态；
- 直接用户表达、评论体验、产品事实、市场结果和系统推导等证据来源；
- 无用户体验结果时，不得把采购理由写成已兑现用户价值。

### F04 用户价值到卖点组合连接

每个用户价值必须连接：

- 支撑参数和能力；
- 支撑卖点；
- 组合内各能力的作用：技术底座、价值强度、互补能力、独立能力或未知；
- 产品事实状态；
- 是否可以独立量化。

同一体验不得被多个技术点重复计价；同源同参卖点必须合并。

### F05 卖点价值强度

卖点价值强度不得由评论条数直接生成。它至少由以下要素组成：

- 产品能力和参数档位；
- 用户是否实际感知到对应结果；
- 正向、负向和矛盾体验；
- 在当前价值战场中的相关度；
- 相对基础方案和同价值竞品的结果差异；
- 数据完整度和事实冲突。

评论数量只说明证据覆盖和稳定性，不是货币价值，也不是购买贡献。

### F06 反事实角色

每个可量化价值组合必须生成三个候选角色：

| 角色 | 最低要求 | 用途 |
| --- | --- | --- |
| 基础价值对照 | 同战场、同品类形态，目标价值缺失或处于较低业务档位 | 估计价值组合的增量 |
| 同价值直接竞品 | 已发布竞品角色成立，提供相似价值，处于真实购买池 | 估计相对选择和实现差异 |
| 上探标杆 | 目标价值明显更强，且用户任务/客群可比较 | 判断更高价值水平和价格上限参照 |

每个候选必须输出可比性：

- 尺寸和产品形态；
- 战场和采购理由重合；
- 价格重叠；
- 共同在售周和渠道；
- 品牌、促销、库存和其他关键配置差异；
- 价值强度差；
- 可用或不可用原因。

### F07 市场分析单元

市场分析以“价值战场 × 尺寸档 × 周期 × 平台/渠道”为基本单元。

每个市场单元至少包含：

- 可售 SKU 集合；
- SKU 真实净成交价；
- 销量、销额和选择份额；
- 促销、库存或异常价格标记；
- 价值组合及业务档位；
- 其他关键配置；
- 品牌和系列；
- M11D 战场贡献权重；
- 数据质量。

M11D 分配权重只能用于战场口径解释和样本权重，不得被当作真实消费者购买归因。

### F08 相对体验增量

在基础对照和同价值竞品可用时，输出：

- 目标用户结果在本品、基础对照和同价值竞品中的表现；
- 正向、负向和问题率差异；
- 用户结果是否更强、相近、更弱或不可判断；
- 结果是否只成立于本品整体，还是可以连接到卖点组合。

用户体验样本的渠道、时间、清洗和去重口径不同，禁止直接比较。

### F09 选择贡献

当共同市场单元、价格重叠和对照质量满足门槛时，估计：

- 同价条件选择差异；
- 价值强度提高一个业务档位后的选择变化；
- 不同相对价差下的选择变化；
- 结果适用的战场、尺寸、渠道和市场窗口；
- 样本量、重叠范围和不确定性。

不满足识别门槛时，只输出整机或战场量价表现，不输出卖点选择贡献。

### F10 市场隐含 WTP

市场隐含 WTP 的估计对象是用户价值组合或具备独立变化的单项能力。

允许两类方法：

1. 高可比匹配对照：其他主要差异受控时，以等选择概率对应的价格差估计价值组合相对承接；
2. 多 SKU 需求模型：使用价格、价值强度、品牌、其他配置、时间、渠道和促销等变量估计选择效用，再由价值效用与价格效用之比计算 WTP。

只有同时满足以下门槛才允许输出金额或区间：

- 基础价值对照成立；
- 目标价值存在至少两个业务档位；
- 价格和选择在样本中存在有效变化；
- 目标价值与其他核心配置不存在无法处理的完全共线；
- 价格系数方向合理且稳定；
- 共同市场单元覆盖达到版本化最低门槛；
- 模型外推不超出观测价格和价值强度范围；
- 敏感性分析方向一致；
- 结果保留方法等级、区间和主要限制。

否则输出以下较低层结果之一：

- 只有用户价值成立；
- 相对体验增量成立；
- 同价选择关联成立；
- 整机相对价格承接成立；
- 当前不可识别卖点 WTP。

### F11 价值存在与量化程度分离

每个价值组合必须分别输出：

- value_status：用户价值是否成立；
- quantification_level：当前量化到哪一层；
- product_role：在产品中的作用；
- monetization_status：市场选择和价格兑现状态。

禁止把以下概念合成一个总标签或总分：

- 有用户价值；
- 是购买理由；
- 是差异化能力；
- 可以量化；
- 可以支撑价格；
- 企业应该增配或减配。

### F12 产品经理结果

主结果名称：

> SKU 产品价值结构与市场兑现

第一屏直接回答：

1. 本品在哪些主要价值战场中竞争；
2. 核心采购理由是什么；
3. 用户实际获得了什么；
4. 哪些卖点组合共同支撑；
5. 相对基础方案和同价值竞品是否存在增量；
6. 当前选择和价格兑现到哪一层。

主表一行一个“价值战场 + 采购理由”：

| 价值战场及市场空间 | 本品核心采购理由 | 用户实际获得的价值 | 支撑卖点组合 | 相对基础与同价值竞品 | 选择和价格兑现 | 产品角色 |
| --- | --- | --- | --- | --- | --- | --- |

主表禁止一行一个孤立参数。

卖点明细进入下钻：

| 卖点/能力 | 在价值组合中的作用 | 产品事实 | 用户体验支撑 | 相对竞品位置 | 能否独立量化 |
| --- | --- | --- | --- | --- | --- |

证据 ID、内部评分、模型变量、SQL、英文状态码和算法过程只进入分析师/QA 附录。

### F13 不生成自动工作清单

V4 输出产品角色和当前可支持的判断，不自动生成：

- 增配、减配或删除；
- 涨价或降价；
- 价格实验方案；
- 用户研究计划；
- 通用下一步工作清单。

没有成本和产品经理设计约束时，系统不得替产品经理做最终配置决策。

## 7. 产品角色与量化语言

### 7.1 产品角色

| 产品角色 | 业务含义 |
| --- | --- |
| 核心差异价值 | 在主要战场中形成用户结果和相对选择优势 |
| 基础门槛 | 缺失会影响入围，具备后不一定产生额外价格 |
| 辅助成交价值 | 支撑整体选择，但不是主要采购理由 |
| 客户获得价值 | 用户和选择价值成立，但价格未完全上收 |
| 配置支撑 | 产品能力存在，但未识别独立用户或市场增量 |
| 价格压力 | 高价位置未得到相应选择和用户结果承接 |
| 当前不可判断 | 事实、样本或反事实不足 |

产品角色与量化程度分别保存，角色不得由单个金额或评论频次决定。

### 7.2 量化层级

| 层级 | 允许输出 |
| --- | --- |
| 用户价值成立 | 用户实际获得的结果、正负体验和适用场景 |
| 相对体验增量 | 相对基础方案和同价值竞品的用户结果差异 |
| 市场选择关联 | 同价或相对价差下的选择差异 |
| 整机价格承接 | 目标 SKU 相对直接竞品的整套方案价差 |
| 市场隐含 WTP | 已通过反事实和模型识别门槛的价值组合金额区间 |

较低层结果不得改写成较高层结论。

## 8. 错误、降级与停止条件

至少覆盖：

| 状态 | 处理 |
| --- | --- |
| 权威画像冲突 | 局部阻断受影响战场或卖点组合 |
| M11C/M11D/M12D 缺失 | 不重建上游；标明当前无法形成完整产品价值结构 |
| 采购理由只有弱表达 | 不升级为核心采购理由或支付价值 |
| 无基础价值对照 | 不估计卖点增量 WTP |
| 只有同价值竞品 | 只输出相对选择和整机/组合价格承接 |
| 价值强度完全共线 | 合并为组合，不拆单项金额 |
| 价格无变化或无重叠 | 不估计价格敏感度或 WTP |
| 促销、库存、异常价污染 | 排除市场单元或降级 |
| 价格系数方向异常 | WTP 置空并输出模型不可识别 |
| 体验口径不可比 | 不输出相对体验强弱 |
| M12C 分摊金额存在 | 只作旧版参考，不进入 V4 WTP 真值 |

任何降级不得通过固定文案补成产品建议。

## 9. 非功能要求

- 首版只读，不新增上游生产写入；
- 默认不调用外部 LLM，核心判断可确定性回放；
- 输出保留 category_code、project_id、version、batch、market_window、confidence 和 evidence refs；
- 同输入和同权威版本产生相同结果 hash；
- 不逐 SKU 或逐评论执行 N+1 查询；
- 所有市场模型保留输入样本 manifest 和版本化配置；
- JSON、短答、Markdown、飞书文档结论一致；
- 旧 V2 和旧 V3 候选稿不受影响；
- 新入口由独立 feature flag 控制，可随时回退。

## 10. 验收场景

### 10.1 65E7Q

必须验证：

- 复用 M11C/M11D/M12D，不重新生成战场和采购理由；
- 高端画质采购理由连接到用户实际画质结果和画质卖点组合；
- MiniLED、高亮、分区和画质处理默认按组合分析；
- 用户只表达整体清晰时，不补写强光、暗场或光晕结果；
- 系统流畅不用于证明 AI 画质兑现；
- 同价值竞品只能支持选择反事实；
- 没有基础价值对照时，不输出画质组合增量 WTP；
- 不消费 M12C 旧分摊金额作为 V4 WTP；
- 主结果按战场和采购理由组织，不输出通用工作清单。

### 10.2 组合可识别样本

至少一个真实或脱敏固定样本满足：

- 同一战场内存在基础、目标和同价值方案；
- 价值强度存在跨档变化；
- 价格、销量和共同在售市场单元足够；
- 能输出相对体验、选择贡献和市场隐含 WTP 区间；
- 结果不拆给组合内高度共线的技术点。

### 10.3 不可识别样本

覆盖：

- 只有同价值竞品；
- 无价格变化；
- 价值强度完全共线；
- 品牌、促销或配置差异无法控制；
- M12D 采购理由为弱表达；
- 产品事实冲突；
- 无用户体验结果。

所有场景必须输出正确层级，不生成伪金额。

## 11. 完成定义

只有同时满足以下条件，V4 才可称为完成：

1. 新需求、详细设计、测试计划和 Goal 任务链经过用户确认；
2. M11C/M11D/M12D 复用合同通过真实数据回放；
3. 采购理由、用户价值和卖点组合连接可追溯；
4. 基础、同价值和上探三类反事实角色可解释；
5. 市场隐含 WTP 仅在识别门槛通过时输出；
6. M12C 旧分摊金额不进入 V4 WTP；
7. 产品经理主结果使用中文业务语义，一行一个战场采购理由；
8. 65E7Q 和可识别/不可识别 cohort 全部通过；
9. 新旧入口平行运行，V4 可回滚；
10. 本地、205 JSON、Markdown 和飞书回读一致。

## 12. NOT in scope

- 不重新生产 M11C 价值战场；
- 不重新生产 M11D 市场空间和销量分配；
- 不重新生产 M12D 采购理由；
- 不推测购买前用户心智；
- 不建设实验平台或实验 WTP；
- 不新增成本、利润、客户剩余或产品投入回报；
- 不自动生成增配、减配、定价或研究任务；
- 不重选竞品；
- 不将高度共线的组合强拆成单卖点金额；
- 首版不把 TV 规则直接套到其他品类。
