# CatForge Analyst 竞品问答 CLI 与小奥 Skill 需求

## 1. 背景

小奥已经能通过 `catforge_analyst` 回答“某 SKU 的竞品有哪些”一类问题，但当前竞品回答还存在六个问题：

1. OpenClaw 直接消费较大的 JSON 时，容易出现解析失败、工具错误外露或自行改写答案。
2. 竞品排序仍偏向“同尺寸、同价位、需求重合、参数相似、销量接近”的通用表达，不能稳定体现专业市场分析判断。
3. 聊天入口适合短结论，不适合承载完整证据矩阵、候选未选原因和详细对比页面。
4. 当前“短结论 + 飞书文档链接”的展现不够直观，用户需要在会话里直接看到类似看板的答案：三款竞品、角色、重合结构、成交影响和证据入口，而不是先打开长文档再理解结论。
5. “关键价值锚点”目前缺少 SKU 级画像和 pair 级可替代性标准，容易把参数/卖点标签直接写成“成交理由偏什么”，让业务用户看不到评分依据。
6. 详细报告把各维度评分依据拆成候选列表式章节，业务用户不容易按“购买池、价值战场、用户任务、目标客群、关键价值锚点、替代压力、市场验证”逐维比较本品和前三竞品。

因此需要把整体链路拆成两个层级：

第一层是 M12D 独立资产生产：先为每个 SKU 生成并发布 `SKU成交理由画像`，判断本品自身有哪些关键价值锚点、证据强度和成交理由角色。

第二层是竞品问答消费 M12D 后生成三个稳定产物：

- CLI 生成可直接发送的短摘要 `short_answer`，控制在 600 个中文字符以内。
- CLI 生成可直接渲染为飞书卡片或前端看板的 `dashboard_payload` 和 `feishu_card_payload`。
- CLI 生成或返回详细分析报告链接 `report_url`，优先落在飞书文档中，作为佐证层而不是主回答。

小奥 Skill 只负责识别意图、调用稳定 CLI、按入口能力发送卡片或短摘要，不再自行解析大 JSON、重写竞品结论或从飞书文档二次提炼看板。

## 2. 核心业务定义

### 2.1 首选竞品定义

首选竞品不是“参数最像”或“价格最近”的 SKU，而是：

> 最容易进入同一批用户最终候选清单，并且会改变用户对目标 SKU 价值判断的 SKU。

系统选择首选竞品必须同时看七类因素：

```text
首选竞品 =
同一购买池
× 主辅价值战场加权重合
× 主辅用户任务加权重合
× 主辅目标客群加权重合
× 关键价值锚点可替代
× 替代压力
× 市场验证
```

其中：

- 同一购买池是前置条件，优先同尺寸、同尺寸档、同价格带或邻近价格带。
- 价值战场、用户任务、目标客群必须区分主辅关系，不能只数重合个数。
- 关键价值锚点来自每个 SKU 的 `SKU成交理由画像`，包括用户愿意付费或优先选择的核心卖点、参数能力、场景价值、评论验证和市场承接。
- 替代压力说明候选 SKU 通过什么方式影响目标 SKU 成交：价格压制、价值替代、配置标杆、品牌/生态替代、下探分流或上探替代。
- 销量只用于验证候选是否具备真实市场分流能力，不能作为首选竞品的主要排序依据。

### 2.2 SKU成交理由画像和关键价值锚点

`SKU成交理由画像` 是 M12D 独立生成和发布的单 SKU 级资产，先回答“这个 SKU 凭什么成交”。它不是竞品 pair 评分，也不是每个 SKU 独占的标签。

每个 SKU 可以有多个关键价值锚点，锚点家族可以在多个 SKU 之间共享。竞品分析时再判断目标 SKU 的核心锚点是否被候选 SKU 覆盖、替代、强化或绕开。

画像必须至少输出：

| 字段 | 业务含义 |
| --- | --- |
| 核心成交理由 | 当前 SKU 最能支撑成交的 1-3 个理由，必须是业务语言。 |
| 关键价值锚点 | 锚点家族和中文名，例如高端画质、游戏流畅、家装融合、预算内配置获得感。 |
| 成交角色 | `core_payment` 核心支付理由、`supporting` 辅助理由、`weak_expression` 弱表达、`risk_drag` 拖累理由。 |
| 证据来源 | 参数事实、事实卖点、评论感知、M12C 卖点支付价值、价值战场、用户任务、目标客群和市场承接。 |
| 证据强度 | 强/中/弱/不足；宣传文本或位置标签不能直接当作强证据。 |
| 置信度 | 按证据完整度、样本可靠性、市场承接和冲突信号综合给出。 |
| 业务解释 | 说明为什么它是成交理由，以及哪些证据只代表厂家表达或弱信号。 |

关键价值锚点的命名原则：

- 单 SKU 资产叫 `SKU成交理由画像`。
- 画像内部核心字段叫 `关键价值锚点`。
- 竞品维度叫 `关键价值锚点可替代性`。
- pair 级结论可以表达为 `成交理由替代强度`。

### 2.3 竞品角色

竞品输出必须至少支持以下业务角色：

| 角色 | 定义 |
| --- | --- |
| 首选直接竞品 | 同一购买池内，对目标 SKU 主支付理由形成最高强度拦截。 |
| 强直接竞品 | 购买池、战场、任务、客群和价值锚点都高度接近，但综合替代压力略低于首选。 |
| 价格贴身竞品 | 价格最接近，但价值战场、任务或客群重合不足以排为首选直接竞品。 |
| 下探分流竞品 | 价格低一个层级或明显更顺，但仍能承接目标 SKU 的部分核心需求。 |
| 上探替代竞品 | 价格更高或品牌/配置更强，可能吸走高预算用户。 |
| 场景替代竞品 | 同尺寸价格不完全贴合，但在某个关键任务、客群或战场上替代性强。 |
| 排除候选 | 有相似点但不足以进入重点竞品，应说明排除原因。 |

## 3. 目标

### 3.1 CLI 目标

`catforge_analyst` 需要把竞品问答升级为可直接面向业务用户的稳定输出：

1. 读取目标 SKU 和候选 SKU 的已发布 M12D `SKU成交理由画像`，作为关键价值锚点和成交理由判断的前置资产。
2. 生成 Top 3 重点竞品摘要，默认只输出三款。
3. 按上述七类因素重新计算竞品业务排序。
4. 角色覆盖只决定候选是否进入 Top 3；入选后的名次必须无条件按报告展示的整数综合分降序排列，同分时依次比较直接竞争关系、市场验证、购买池得分和价格接近度。关键价值锚点和替代压力门槛只能限制竞品角色及强替代话术，不能改变名次。
5. 输出每款竞品的角色、替代压力、关键重合点、关键差异、关键价值锚点可替代性和市场验证。
6. 输出可直接发送给飞书/聊天入口的 `short_answer`。
7. 输出卡片看板 payload，固定呈现 Top 3、重合强度、命中点、成交影响、市场验证和证据入口。
8. 输出详细报告 payload，并在配置可用时生成飞书文档 `report_url`。
9. 在 JSON 中保留可复核字段，但不要要求 Skill 解析大 JSON 后再写答案。

### 3.2 Skill 目标

小奥 Skill 需要做到：

1. 识别“竞品是谁”“为什么选第一款”“和谁竞争”“直接竞品有哪些”等竞品意图。
2. 优先调用 CLI 的稳定竞品摘要命令。
3. 在飞书入口把当前会话 `message_id` 传给 `competitor-set`，并追加 `--feishu-card-only`，由 CLI 尝试用 bot 发送 `feishu_card_payload`；本轮可见文本只发送 CLI stdout 中的卡片发送状态。
4. 在纯文本入口如果 CLI 返回 `short_answer`，必须原样发送，不得改写语气、重排名次或增删关键结论。
5. 如果 CLI 返回 `report_url`，卡片和短摘要都必须提供完整报告入口。
6. 如果 CLI 返回多候选 SKU，必须让用户二次选择；飞书入口可渲染为选择卡片。
7. 如果 CLI 失败，必须给业务化失败提示，不暴露命令、JSON、stderr、堆栈、内部模块名或调试文本。

## 4. 非目标

本次不做以下事项：

- 不重跑 M00-M11D，也不改变事实层、语义层和市场图谱的生成逻辑。
- 不把 OpenClaw 变成竞品排序引擎。
- 不要求聊天回答展示完整证据矩阵。
- 不新建一套独立竞品排序程序；竞品看板能力必须复用现有 `competitor-set`。
- 不在竞品问答流程里生成 M12D。M12D 是独立模块，必须先完成生成、验证和发布；竞品分析智能体只读取已发布画像，不能继续在 pair 评分时临时拼接“成交理由”。
- 不在聊天回答中展示内部 code、批次号、表名、字段名、规则版本、命令文本或原始 JSON。
- 不把链接预览作为主回答路径；链接预览只用于后续“用户发送报告链接后自动展开摘要”的补充场景。
- 不把累计销量作为竞品排序主依据。
- 不把服务履约、物流安装、售后体验作为产品竞品主线。
- 不把低价 SKU 简单判定为更强竞品；必须说明其是否仍在同一购买池和同一成交理由中。
- 不把“价格价值表达”“性价比提及”等位置标签直接写成强成交理由；只有参数、卖点、评论或市场承接能够支撑时，才可进入核心成交理由。

## 5. 输入数据

竞品问答必须使用已经生成的事实和图谱结果，不直接读取原始四张表做业务结论。

| 数据 | 作用 |
| --- | --- |
| SKU 解析结果 | 确定目标 SKU，处理同名、模糊型号、Pro/非 Pro 混淆。 |
| M03B 参数事实画像 | 尺寸、尺寸档、核心参数能力、参数档位。 |
| M04C 卖点事实画像 | 标准卖点、卖点维度、卖点是否有参数支撑。 |
| M05C 评论事实画像 | 评论中的用途、人群、价值感知、正负向支撑、竞品提及。 |
| M07 市场画像 | 尺寸内价格带、周均销量、均价、平台结构、观察周。 |
| M09C 用户任务画像 | 主/辅/机会/拖后腿用户任务。 |
| M10C 目标客群画像 | 主/辅/观察/潜在/未满足客群。 |
| M11C 价值战场画像 | 主/辅/机会/品牌声明/用户观察/拖后腿战场。 |
| M11D 语义市场图谱 | 各战场、任务、客群的 SKU 覆盖和销量分配。 |
| M12C 卖点价值量化 | SKU×卖点价值角色、可比产品价格/销量/销额差异、本品可解释价差/销量差份额、竞品拦截、补强建议和拖后腿卖点。 |
| M12D SKU成交理由画像 | SKU 级核心成交理由、关键价值锚点、证据强度、置信度和弱表达/拖累标记。 |
| pairwise 销量重叠 | 重叠在售周内周均销量、均价、销额、平台结构。 |

## 6. 竞品选择需求

### 6.1 候选池

候选池必须先从购买池收敛，再做语义和价值判断。

优先级：

1. 同 SKU 尺寸，且同尺寸价格带或邻近价格带。
2. 同 M03B 五档尺寸段，且同尺寸段价格带或邻近价格带。
3. 同价值战场强重合，但价格偏离明显的上探或下探候选。
4. 用户任务、目标客群高度重合，但尺寸或价格偏离的场景替代候选。

必须输出候选进入池的原因，避免用户看到“很多大屏高画质电视都相似，为什么就是这三款”的疑问。

### 6.2 主辅加权重合

价值战场、用户任务、目标客群不能只计算重合数量。必须使用关系状态权重。

建议权重口径：

| 关系状态 | 权重 |
| --- | ---: |
| 主战场 / 主任务 / 主客群 | 1.00 |
| 辅战场 / 辅任务 / 辅客群 | 0.75 |
| 用户观察成立 | 0.45 |
| 机会 / 潜在 | 0.35 |
| 品牌声明 | 0.25 |
| 未满足 / 拖后腿 | -0.30 |
| 排除 / 不支持 | 0 |

评分必须体现主辅相互命中：

- 目标主项命中候选主项，权重最高。
- 目标主项命中候选辅项，仍然是强命中。
- 目标辅项命中候选主项，可说明候选在该方向更聚焦。
- 机会、潜在、品牌声明只能作为补充，不能单独把候选推为首选竞品。
- 拖后腿和未满足是风险，不得被当成正向重合。

### 6.3 关键价值锚点可替代性

关键价值锚点必须先由 M12D 在单 SKU 上成像，再在竞品 pair 中比较可替代性，不得直接从参数 code、卖点 code 或文字位置标签拼接结论。

对电视品类，价值锚点至少包括：

- 尺寸和空间升级价值。
- 画质和显示体验。
- 高刷、游戏和运动流畅体验。
- 影音沉浸。
- 智能互联和易用。
- 护眼和长时间观看。
- 外观、贴墙、家装融合。
- 预算内配置获得感。

系统必须判断候选 SKU 是否在目标 SKU 的核心支付理由上提供了可替代方案，而不是仅说明“参数相似”。

关键价值锚点可替代性按 15 分维度进入竞品评分，建议口径：

| 评分项 | 分值 | 判断标准 |
| --- | ---: | --- |
| 目标核心锚点覆盖 | 5 | 候选是否覆盖目标 `core_payment` 锚点，主锚点覆盖高于辅助锚点覆盖。 |
| 证据强度对等 | 4 | 候选是否同样有参数事实、事实卖点、评论感知、M12C 支付价值或市场承接支撑。 |
| 候选相对优势 | 3 | 候选是否在目标核心锚点上更强、更清晰或更容易被用户理解。 |
| 场景/任务/客群一致 | 2 | 锚点是否落在同一主价值战场、主用户任务和主目标客群中。 |
| 市场与评论验证 | 1 | 候选是否有重叠在售周销量、正向评论或低冲突信号支撑。 |

评分硬约束：

- 只有宣传文本、位置标签或泛化“性价比”表达，没有事实/评论/市场支撑时，该锚点最多按 `weak_expression` 参与，不得作为强替代理由。
- 目标 SKU 的 `core_payment` 锚点缺失时，必须降置信度并提示“成交理由画像不足”，不能用 fallback 话术补写“技术型/场景型高端体验”。
- 候选只覆盖目标辅助锚点，不能单靠该维度成为首选直接竞品。
- 候选在目标核心锚点上形成拖累或负评重合时，应降低替代性，而不是把重合当作正向。

分数解释必须使用区间：

| 分数 | 业务解释 |
| ---: | --- |
| 13-15 | 候选几乎完整替代目标核心成交理由，且证据强度接近或更强。 |
| 10-12 | 候选覆盖主要成交理由，但仍有部分锚点、证据或场景弱于目标。 |
| 7-9 | 只有局部锚点替代，适合解释强直接或价格贴身，但不足以单独支撑首选。 |
| 0-6 | 关键成交理由替代不足，不能把“参数相似”写成强竞品。 |

### 6.4 替代压力

替代压力是 pair 级结果，不是每个 SKU 的独有画像。每个入选竞品都必须生成替代压力说明，并说明它如何影响目标 SKU 的成交。

| 替代压力 | 判断口径 |
| --- | --- |
| 价值替代压力 | 在同一购买池内，承接相同主战场和主客群，且关键价值锚点可替代。 |
| 价格压制压力 | 价格更低但仍保留目标 SKU 关键成交理由，削弱目标 SKU 溢价解释。 |
| 配置标杆压力 | 参数或卖点能力更强，抬高用户对目标 SKU 的配置预期。 |
| 场景心智压力 | 在目标 SKU 重要场景中表达更清晰，例如客厅空间、家装融合、游戏场景。 |
| 品牌/生态压力 | 品牌心智、系统生态、渠道表达使其进入同一候选清单。 |
| 下探分流压力 | 用户降低预算后仍能满足部分核心需求。 |
| 上探替代压力 | 用户追加预算后能获得更明确的高端理由。 |

替代压力按 10 分维度进入竞品评分，建议口径：

| 评分项 | 分值 | 判断标准 |
| --- | ---: | --- |
| 购买池压力 | 2 | 是否同尺寸、同尺寸档、同价带或邻近价带，会不会进入同一次预算决策。 |
| 成交理由替代强度 | 3 | 是否覆盖目标核心成交理由，直接读取关键价值锚点可替代性结果。 |
| 价格或配置冲击 | 2 | 是否以更低价格、更强配置或更清晰权益改变用户对目标 SKU 的价值判断。 |
| 场景心智迁移 | 1 | 是否把同一锚点转译成更强场景表达，例如客厅、游戏、家装或家庭长看。 |
| 市场分流验证 | 1 | 重叠在售周是否具备真实成交，且样本不是极低。 |
| 风险/置信修正 | 1 | 样本不足、服务信号过重、证据冲突或仅厂家主张时扣分。 |

替代压力必须输出主压力类型和辅助压力类型。主压力类型用于竞品角色和摘要；辅助压力只进入报告解释，不能把一个候选同时写成所有压力都强。

### 6.5 市场验证

市场验证只回答“这是不是纸面竞品”：

- 使用重叠在售周的周均销量、周均销额、均价和平台结构。
- 用于验证候选是否有真实成交能力。
- 不用累计销量作为排序依据。
- 不把销量接近度写成“选择竞品”的核心证据。
- 若候选销量极低或重叠周不足，应降低置信度或标注样本限制。

### 7.5 详细飞书报告要求

飞书报告必须承载聊天卡片中放不下的完整分析。它是看板的佐证层，不是主回答展现内容。

报告必须包括：

1. 标题：`{目标品牌}{目标型号} 重点竞品分析报告`。
2. 结论摘要：三款竞品、各自角色、核心替代压力。
3. Top 3 竞品卡：价格、尺寸、周均销量、主要角色、综合竞争强度；不单列替代压力。
4. 维度化分析过程：按购买池、价值战场、用户任务、目标客群、关键价值锚点、替代压力、市场验证分别成章。
5. 每个维度章节都必须包含：判断口径、本品 + Top 3 横向表、各竞品得分/强弱差异、业务结论。
6. SKU成交理由画像：先展示目标 SKU 的核心成交理由，再展示前三竞品的成交理由画像，说明哪些锚点共享、哪些是目标独有、哪些是候选更强。
7. 卖点价值量化：按目标 SKU 和前三竞品列出核心卖点商业价值、价格溢价卖点、销量驱动卖点、基础门槛卖点、组合型增值卖点、竞品拦截与补强建议、卖点有效市场、可比产品价格/销量差异、本品可解释价差/销量差份额和证据支撑强度。
8. 其他候选为什么未入选：作为附录或折叠区展示价格过远、场景偏离、主客群不同、仅参数相似、销量验证不足等，不作为“分析过程”的主目录。
9. 口径说明：当前样本范围、线上渠道限制、重叠周口径、销量只是市场验证，M12C 卖点价值是同尺寸价格带和业务市场场景内的可观测估计，不是严格因果。

报告“分析过程”目录必须采用以下结构：

```text
二、分析过程
2.1 综合评分总览
2.2 购买池比较
2.3 价值战场比较
2.4 用户任务比较
2.5 目标客群比较
2.6 关键价值锚点可替代性比较
2.7 替代压力比较
2.8 市场验证比较
2.9 候选池与未选原因附录
```

候选池不得单独作为主分析章节放在所有维度之前。候选池只回答“哪些 SKU 被纳入/排除”，不能替代每个维度对本品和前三竞品的横向解释。

报告当前不输出产品经理策略、导购话术、应对策略或泛化建议。需要建议类问题时，由独立 SOP 另行生成。

报告中的销量、周均销量、空间销量等“台数”必须展示为整数台，不展示 `113,034.5台` 这类小数台。价值战场、用户任务、目标客群的图谱空间缺失时，不得输出“图谱空间待生成”“暂无该分类市场空间数据”“当前图谱未分配本品销量”等技术提示，应使用业务可读的口径说明：`market_space` 缺失时写“本轮未计算该语义维度销量空间”；SKU 在主辅维度内暂未分配销量时写“本轮未分配该 SKU 在此维度的销量”；机会、拖后腿、评论观察等补充关系没有销量分配时写“本轮未做销量归因，仅作机会或观察证据”。

空调报告的市场画像必须使用 M07 的“匹数段 × 价格带”同池口径。3匹柜机和 3匹以上柜机统一展示为“3匹及以上柜机”；1.5匹挂机等大样本段必须通过价格带继续拆分，不得只按匹数段展示一个过大的同池空间。若历史数据仍存在 `floor_hp_3_plus`，报告层必须按 3匹及以上柜机解释，不能输出单 SKU 池排名作为竞争力结论。

### 7.6 卖点价值量化要求

竞品比较报告中的“溢价卖点”必须优先使用 M12C，而不是只用“事实卖点 + 评论正向支撑”推断。

报告必须把“卖点画像”和“卖点价值量化”分开：

- 卖点画像只展示事实卖点、评论支持/反向、参数支撑、需复核表达和共同价值锚点。
- 卖点价值量化单独成章，横向对比和每个产品画像中都必须展示。

每个 SKU 的卖点价值量化至少展示：

| 项目 | 业务含义 |
| --- | --- |
| Top5 核心卖点商业价值 | 按强溢价、强销量、组合型增值、机会/拦截和拖后腿风险综合排序，只展示前 5 个，避免长表淹没重点。 |
| 强溢价卖点 | M12C `premium_driver_estimated`，表示有卖点组在同池价格差异为正，且本 SKU 有参数/评论/语义支撑。 |
| 强销量卖点 | M12C `sales_driver_estimated`，表示价格差异不作为价格支撑，但同池有正向周均销量或销额差异。 |
| 组合型增值卖点 | M12C `value_bundle_claim`，表示单项价格支撑不强，但与主战场、主任务、主客群共同组成成交理由。 |
| 基础门槛卖点 | M12C `basic_threshold`，表示用户期望具备但不一定形成额外溢价的卖点。 |
| 用户感知不足卖点 | M12C `weak_user_perception_claim`，表示厂家有表达或参数存在，但评论、任务或市场验证不足，不得作为正向溢价依据。 |
| 高价竞品拦截/价格上探机会 | M12C `high_price_competitor_intercept` / `price_up_opportunity`，表示同池高价或高成交竞品具备、本品缺失或表达弱的卖点。 |
| 厂家主张卖点 | M12C `brand_claim_only`，表示厂家表达较强但市场或评论验证不足。 |
| 机会缺口 | M12C `opportunity_gap`，表示竞品或同池强 SKU 具备且有市场价值，本品缺失或表达弱。 |
| 拖后腿卖点 | M12C `drag_factor`，表示评论、参数或语义支撑不足，会削弱成交理由。 |
| 可比池卖点价格/销量差异 | 有卖点组与对照组的可观测差异，只能作为解释性证据，不能写成“该卖点导致价格/销量增加”。 |
| 本品可解释价差/销量差份额 | 本品相对可比产品基准的价格、周均销量或周均销额差异，按卖点证据权重做解释性分摊。负向、感知不足或拖后腿卖点不得展示为正向分摊。 |

如果某 SKU 没有 M12C 结果，报告可以退回事实卖点口径，但必须写成“卖点价值量化待生成”，不得伪造量化指标。

## 8. Skill 功能需求

小奥 Skill 需要新增竞品问答专项规则。

### 8.1 路由规则

以下问题必须路由到竞品摘要 CLI：

- “某 SKU 的竞品有哪些”
- “和谁竞争”
- “直接竞品是谁”
- “第一款为什么选它”
- “为什么创维 65A7H PRO 是海信 65E7Q 的首选竞品”
- “哪些 SKU 会抢这款的订单”

### 8.2 输出规则

Skill 必须遵守：

1. 在飞书入口，Skill 不解析或拼装卡片 JSON，必须调用带 `--feishu-reply-message-id` 的稳定 CLI，由 CLI 使用 `msg_type=interactive` 尝试回复卡片。
2. 飞书入口必须追加 `--feishu-card-only`；CLI stdout 必须是卡片发送状态。发送成功时可见回复为“已发送飞书竞品看板卡片”，发送失败时可见回复为业务安全失败原因；禁止退回长文本答案掩盖卡片失败。
3. 不把 `top_competitors` 重新组织成另一套口径。
4. 不自行补充泛化市场常识。
5. 不暴露英文内部字段和技术模块。
6. 不在答案末尾生成“需要我继续分析吗”一类通用客服语。
7. 后续追问“第一款”“它”“上面那个”时，必须沿用上一轮上下文中的候选，而不是重新模糊解析。

### 8.3 异常规则

| CLI 状态 | Skill 回答要求 |
| --- | --- |
| `ambiguous` | 列出候选 SKU，让用户选择；飞书入口可用卡片。 |
| `not_found` | 说明当前分析样本未找到该型号，请用户补充品牌、型号或 SKU code。 |
| `unsupported` | 说明当前数据暂不支持该问题，并给出可替代问题。 |
| `error` | 说明当前竞品分析包未能生成，不输出内部报错。 |
| `report_failed` | 仍发送短摘要，并说明详细报告暂未生成。 |

## 9. 验收问题

首轮验收使用海信 65 寸电视，不再使用红米样例。

验收问题：

1. “海信 65E7Q 的竞品有哪些？”
2. “为什么创维 65A7H PRO 是海信 65E7Q 的首选竞品？”
3. “TCL 65Q9L PRO 和创维 65A7H PRO 哪个对海信威胁更大？”
4. “为什么小米 L65MC-SP 价格更接近但不是首选竞品？”
5. “详细分析报告链接是什么？”

验收标准：

- 第一问返回三款重点竞品，且聊天摘要不超过 600 字。
- 飞书入口第一问优先返回看板卡片，卡片首屏能看到 Top 3、竞品角色、三类重合结构和完整报告入口。
- 第一名不是简单按价格最近或销量接近排序。
- 能解释“很多 65 寸高画质电视都相似，为什么这款排第一”。
- 能说明小米 L65MC-SP 是价格贴身竞品，但因任务、客群或价值锚点重合不足，不排第一。
- 能展示目标 SKU 的 `SKU成交理由画像`，并说明关键价值锚点可替代性如何影响前三竞品排序。
- 详细报告能打开，且报告中有候选未选原因。
- 详细报告“分析过程”按维度比较本品和 Top 3，不把候选池放成主分析章节。
- 回答中不出现 CLI、Mxx、JSON、命令、stderr、内部 code、英文 price band。

## 10. 测试要求

测试必须不依赖真实飞书 API 和外部 LLM。

必须覆盖：

- SKU 模糊解析，尤其 Pro/非 Pro 混淆。
- M12D 消费契约：目标 SKU 和 Top 3 候选必须能读取已发布 `SKU成交理由画像`；缺失时降级或阻断，不在竞品问答中补跑。
- 主辅价值战场加权重合。
- 主辅用户任务加权重合。
- 主辅目标客群加权重合。
- 关键价值锚点可替代性评分，目标核心锚点覆盖高于辅助锚点覆盖。
- 只有价格价值表达或厂家主张、缺少事实/评论/市场支撑时，不得生成强成交理由。
- 替代压力评分和压力类型，必须消费购买池、语义重合、价值锚点可替代性、价格/配置冲击和市场验证。
- 价格最近但语义弱的候选不得排第一。
- 销量相近不得单独推高为首选竞品。
- `short_answer` 不超过 600 中文字符。
- `short_answer` 不包含内部字段、命令、模块或 JSON。
- `dashboard_payload` 只包含 Top 3 主看板信息，且每款竞品必须包含价值战场、用户任务、目标客群三类重合结构。
- `dashboard_payload` 和 `feishu_card_payload` 不包含 `BF_`、`TASK_`、`TG_` 等内部 code。
- `feishu_card_payload` 可 JSON 序列化，卡片消息体大小符合飞书限制。
- 飞书报告生成失败时仍可返回短摘要。
- 飞书卡片发送失败时仍可返回短摘要和报告链接给结构化调用方，但飞书入口的 `--feishu-card-only` stdout 必须输出业务安全失败原因，不产生空回复。
- 不带飞书消息参数的 `--format text` 输出与 JSON 中 `short_answer` 一致；带 `feishu_card_delivery` 的 text 输出优先返回卡片发送状态。
- 竞品详细报告必须把卖点画像和卖点价值量化拆开：卖点画像展示事实，卖点价值量化展示 M12C 的核心卖点商业价值、可比产品差异、本品可解释价差/销量差份额和业务标签。
- 竞品详细报告的“分析过程”必须按维度组织，每个维度比较本品和 Top 3，不得把关键价值锚点、替代压力和市场验证合并成一个难以理解的章节。
- 候选池和未选原因只能作为附录或折叠区，不得作为主分析目录替代维度比较。
- M12C 缺失时报告明确提示“卖点价值量化待生成”，并用事实卖点/评论支撑作为兜底，不得伪造指数。

## 11. 与旧 M12-M15 的关系

旧 M12-M15 是传统核心三竞品结果链路，保留历史兼容。

本需求面向小奥问答入口，不要求沿用旧三槽位输出。它消费 M03B/M04C/M05C/M07/M09C/M10C/M11C/M11D/M12C 和已发布 M12D 等新版事实、语义资产、卖点价值量化结果和 SKU成交理由画像，生成适合聊天、飞书卡片看板和飞书报告的业务问答结果。

后续如果旧 M12-M15 继续演进，应把本需求中的首选竞品定义、主辅加权重合、看板 payload 和报告话术约束同步进去。

## 12. 产品经理可读性与业务语义治理

### 12.1 报告必须回答的业务问题

报告首屏和分析结论必须按以下顺序回答，不得先解释算法：

1. 当前最值得关注的三款竞品是谁。
2. 它们为什么会进入同一批用户的购买选择。
3. 每款竞品在哪些成交理由上与本品重合、补强或错位。
4. 替代压力到底是强、中、弱，还是当前证据不足以判断。
5. 哪些结论有充分证据，哪些只能作为观察项。

`Top 3` 只表示当前候选中的相对排序，不自动代表三款都构成强替代。若 Top 1 的关键价值锚点或替代压力未达到强竞争门槛，报告必须称为“重点观察第一”或“当前候选第一”，不得写成“最完整替代关系”“首选直接竞品”或“最可能影响最终成交”。

### 12.2 替代压力表达

替代压力必须把以下信息分开输出：

| 信息 | 业务问题 |
| --- | --- |
| 分数与等级 | 压力到底强还是弱 |
| 可评估状态 | 当前证据是否足以支撑该等级 |
| 压力来源 | 价格、配置、场景、品牌或成交理由中的哪一种形成压力 |
| 业务影响 | 直接分流、潜在分流、同池观察或暂不判断 |
| 复核状态 | 是否需要补证据或人工复核 |

低分可以直接表达为“替代压力弱（3/10）”。证据不足只能作为单独的结论边界，不能被写成压力来源。`低替代压力复核` 不得作为压力类型或业务结论出现。

报告中的替代压力固定按“判断结果、判断依据、业务含义、证据边界”四段表达，不得把多个独立判断拼成一条强因果句。

### 12.3 内部代码零泄漏

`risk_flags`、`gate_reasons`、`missing_reason_code`、`quality_flags`、taxonomy code、模块代码、字段名和技术状态码只允许保留在数据库、JSON 和技术验收产物中。飞书报告、卡片和短回答只能消费中文业务展示字段。

中文语义来源分为：

- 品类战场、用户任务、目标客群、标准卖点和成交理由：读取对应 TV/AC 已发布 taxonomy 的中文名称。
- 公共风险、缺失、降级和门槛原因：读取 Core3 公共业务语义目录。
- 竞品角色、替代压力和业务影响：读取竞品分析业务语义目录。

业务输出不得使用 `mapping.get(code, code)` 回退原始代码。未知代码必须记录为发布校验错误并阻断外部业务报告，不能把英文 code 展示给用户。

### 12.4 信息密度和重复控制

- 分析结论最多保留“总判断 + Top 3 各一条 + 证据边界”，不得把七个维度重新逐段复述一遍。
- 每个分析维度只保留一张本品与 Top 3 横向表和一条基于实际分数的差异结论。
- 产品画像只展示与竞品判断有关的主项、差异项和证据边界；完整底层量化明细留在技术审计产物。
- 相同卖点、相同市场场景或相同口径说明不得在同一产品画像中重复出现。
- 报告不得用“高度交叉”“最完整”“真实分流”“直接拦截”等强词替代实际分数判断。

### 12.5 新增验收门禁

- 弱替代压力样例必须直接显示弱分数，不出现“威胁来自低替代压力复核”。
- 证据不足样例必须把“当前测算”和“证据边界”分开，不能由证据不足推出成交影响。
- Top 1 未达到直接竞品门槛时，结论必须说明它只是当前候选中的相对第一。
- 报告、卡片和短回答不得出现 snake_case、`BF_`、`TASK_`、`TG_`、`Mxx` 或原始参数 code；型号、单位和正式产品名除外。
- 看板与正文使用同一市场销量字段，不能一处显示“待复核”、另一处显示确定数值。
- TV 与 AC 分别做报告快照测试，AC 不得出现电视专属的“技术型/场景型高端体验”兜底文案。

## 13. 产品经理业务对比报告

### 13.1 输出物定位

竞品分析必须形成三个相互独立的业务输出物：

1. 重点竞品结论卡：回答本品当前最需要关注哪三款产品。
2. 产品经理业务对比报告：回答本品与三款重点竞品在用户可见价值上分别是什么、相同在哪里、差异在哪里。
3. 分析佐证报告：解释竞品为何入选、各维度如何评分、证据来自哪里以及结论边界。

三个输出物使用固定命名模板，避免把新增业务对比报告误认为原详细分析文档的改版或替代：

| 输出物 | 固定名称模板 | 用途 |
| --- | --- | --- |
| 飞书结论卡 | `{本品型号} 重点竞品结论` | 快速回答三款重点竞品是谁 |
| 新增产品经理飞书文档 | `{本品型号} 与重点竞品的用户选择对比报告` | 比较四款产品在用户可见价值上的共同点、差异和取舍 |
| 原竞品详细分析飞书文档 | `{本品型号} 重点竞品识别与分析依据报告` | 保留竞品识别过程、维度评分、证据引用和结论边界 |

新增的“用户选择对比报告”与原“重点竞品识别与分析依据报告”必须分别生成、分别发布并返回两个独立 URL。新增报告不得覆盖、改名复用或替代原详细分析文档。

产品经理业务对比报告不是分析佐证报告的摘要，也不是“为什么它们是竞品”的重复说明。它只消费已经发布的市场画像、参数画像、卖点画像、价值战场画像、用户任务画像、目标客群画像、M12C 卖点价值量化、M12D SKU 购买理由画像和 pair 级替代压力，不在报告阶段重新生成画像或推导新的产品策略。

该报告不得输出没有数据支撑的产品动作、传播动作、价格动作、销量增量预测、渠道推断或验证方案。某个业务问题无法由现有数据回答时，直接不设该章节或不展示该结论，不使用泛化建议填补空白。

### 13.2 报告必须回答的业务问题

报告目录使用产品经理熟悉的业务问题，不直接使用算法维度名：

1. 四款产品分别卖多少钱、卖得怎么样。
2. 四款产品真正强在哪里。
3. 用户购买这类产品时主要比较什么。
4. 用户买回去主要解决什么问题。
5. 哪些用户需求更容易被各款产品吸引。
6. 四款产品重点讲什么，用户实际理解了什么。
7. 用户为什么会选择四款产品。
8. 用户在四款产品之间会怎样取舍，差异最终体现在哪里。

每章必须把本品和三款竞品放在同一张横向表中。不得为三个竞品分别生成三套重复章节；需要展示 pair 级替代压力时，也必须汇总到一张“竞品对本品的替代关系”表中。

### 13.3 各画像在业务报告中的职责

| 已发布画像或结果 | 在业务报告中回答的问题 | 不得越界回答的问题 |
| --- | --- | --- |
| 市场画像 | 价格、周均销量、同池排名和份额分别处在什么位置 | 为什么销量高、采取什么动作能提升销量 |
| 参数画像 | 产品实际具备哪些能力，哪些可比参数存在明确差异 | 单个参数值多少钱、单个参数导致多少销量 |
| 价值战场画像 | 用户在选择这类产品时主要比较哪些体验 | 用户最终为什么购买某一个 SKU |
| 用户任务画像 | 产品主要承接哪些使用场景和使用问题 | 把场景重合直接写成成交理由 |
| 目标客群画像 | 哪类需求特征的用户更容易被产品吸引 | 没有证据的年龄、收入、家庭阶段等人口标签 |
| 卖点画像 | 产品重点表达什么，哪些表达有事实和评论支撑，哪些出现反向反馈 | 把产品表达直接当作用户购买理由 |
| M12C 卖点价值量化 | 哪些卖点具有相对商业价值证据，哪些只是基础门槛或弱表达 | 把观察性价差写成用户愿付金额或因果贡献 |
| M12D SKU 购买理由画像 | 用户选择该 SKU 时可成立的核心和辅助购买理由 | 用品类通用价值替代 SKU 独有购买理由 |
| pair 级替代压力 | 竞品在哪些购买理由上可能替代本品，替代程度强弱如何 | 把低压力、证据不足或复核状态写成威胁来源 |

价值战场、用户任务和购买理由必须保持业务含义分离：

- “用户主要比较什么”是品类选择标准。
- “用户买回去解决什么”是使用场景和任务。
- “用户为什么选择这款”是 SKU 级购买理由。

三者可以引用同一证据主题，但不得使用同一句结论互相替代。

### 13.4 四产品统一比较规则

- 所有核心表固定以“本品、竞品 1、竞品 2、竞品 3”为四个产品列，同一行使用同一口径。
- 表格先展示共同点，再展示真正有区分度的差异；四款都具备的基础能力不得写成某款独有优势。
- 参数高低只在同口径、同单位且品类规则确认方向可比时输出“领先/接近/落后”；缺失值显示“暂不能判断”，不得作为落后。
- 画像关系统一显示为“重点、支撑、观察、未形成、暂不能判断”；不得用模糊强词替代实际关系状态。
- 目标客群以需求特征表达，例如“重视亮场画质”“经常观看体育或玩游戏”“重视客厅融合”，不得自动生成人口学故事。
- 市场表现只作为同期观察结果与画像并列展示，不得反向证明某项卖点或购买理由成立。
- 每章结尾最多输出两句：一句说明四款共同争夺什么，一句说明真正差异是什么。没有稳定差异时直接写“当前未识别到稳定差异”。

### 13.5 用户价值传达一致性

报告必须在四款产品横向比较之外，对每款产品分别检查以下链路：

```text
产品事实 -> 产品重点表达 -> 用户正向/反向感知 -> SKU 购买理由
```

市场价格和销量放在链路旁作为观察结果，不作为链路成立条件。允许输出的业务状态只有：

| 状态 | 判定要求 | 产品经理可见表述 |
| --- | --- | --- |
| 传达完整 | 有产品事实、有对应卖点表达、有用户正向感知，并进入 M12D 核心或辅助购买理由 | 该价值已从产品能力形成稳定购买理由 |
| 已被感知 | 有产品事实和用户正向感知，但尚未进入稳定购买理由 | 用户已经感知该能力，当前未形成稳定购买理由 |
| 只停留在表达 | 有事实和卖点表达，但缺少用户感知或购买理由证据 | 产品已经重点表达，用户侧尚未形成稳定认知 |
| 存在体验分歧 | 卖点主题存在稳定反向评论证据 | 用户对该体验存在分歧 |
| 暂不能判断 | 关键事实、评论或 M12D 结果缺失 | 不输出链路结论 |

不得根据销量高低把“只停留在表达”升级为“传达完整”，也不得根据销量低把已经成立的用户感知降级为无效。

### 13.6 产品经理报告验收

- 报告存在独立标题和独立飞书链接，不与分析佐证报告共用正文目录。
- 第一张总表同时展示本品和三款竞品，不合并三个竞品表现。
- 报告包含参数、用户比较内容、使用任务、需求型客群、卖点传达、购买理由和替代关系的横向比较；没有有效数据的维度整章省略。
- 每个可见结论能回溯到已发布画像或结构化评估结果，但正文不展示算法过程和内部代码。
- 报告不出现“价值战场、关键价值锚点、替代压力、WTP、市场验证”等内部分析术语，统一翻译为直接业务问题。
- 报告不输出产品动作、传播动作、价格动作、渠道推断、销量预测或验证方案。
- 四款产品的事实、表达、用户感知和购买理由不得混写成一层。
- 相同主题在不同画像中出现时，必须按“比较内容、使用问题、购买理由”的职责分别表达，不得重复同一句话。
