# M12D 购买理由成立度、购买阻力与产品价值主张分层需求

版本：`v0.1-draft`

日期：`2026-07-11`

## 1. 背景

M12D 当前把正向购买理由证据、评论冲突、M12C 负向、市场样本风险和输入质量扣分汇入同一锚点评分。该设计容易混淆三个业务问题：

1. 这个 SKU 是否具备某项产品价值主张。
2. 用户是否已经把该价值理解为购买理由。
3. 该购买理由是否同时承受负面评价或市场阻力。

QF15A 对 TV 139 个无核心 SKU 的审计表明：

- 在 7 分分层门槛、评论同维度和理由业务边界成立后，可形成 37 个有核心理由 SKU。
- 另有 29 个 SKU 的正向购买理由证据已成立，但被普通评论冲突或 M12C 局部负向拦截；这些负向不是 `comment_negative_dominates`，不应直接否认购买理由存在。
- 另有 29 个 SKU 只有 `参数事实 + 官方卖点 + 语义场景`，主要对应“家庭操作更省心”和“新家家装更适配”。这只能证明产品价值主张，不能证明用户已经把它当成购买理由。

本需求以此为依据，重构 M12D 的证据和消费契约。

## 2. 目标

1. 将“购买理由成立度”和“购买阻力画像”拆成两个独立、可追溯维度。
2. 将“产品价值主张”和“用户已验证购买理由”分层，不再把产品设计意图直接当成交理由。
3. 普通负面评价、局部评论冲突和 M12C 负向只形成压力标签，不删除已成立的购买理由。
4. 只有正向证据本身无效、事实被证伪或证据未达到最低成立门槛时，购买理由才不成立。
5. 没有核心购买理由的 SKU 仍可消费参数、卖点、市场、价值战场和产品价值主张，不得把整个 SKU 或整个版本统一判为不可用。
6. TV 和 AC 使用共享 typed contract，但分别使用本品类 taxonomy、理由边界、市场池和阈值。

## 3. 非目标

- 不新增或伪造用户评论。
- 不把产品销量因果归因给单一购买理由。
- 不在竞品智能体中生产 M12D。
- 不用 SKU、品牌白名单恢复覆盖率。
- 不为了通过发布门槛删除真实负面证据。
- 不把 TV 的理由、尺寸或价格边界复制到 AC。

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| 产品价值主张 | 参数、卖点和目标场景共同表达的产品意图，回答“产品希望给用户什么价值”。 |
| 用户购买理由 | 用户感知、选择表达、市场承接或 M12C 正向证据支持的决策解释，回答“用户为什么选择这个 SKU”。 |
| 购买理由成立度 | 仅根据正向、同锚点证据判断理由是否成立及强度。 |
| 用户承接状态 | 用户评论、选择证据、市场承接和 M12C 是否支持该理由。 |
| 购买阻力 | 与已成立理由并存的负面评论、体验争议、M12C 负向或市场压力。 |
| 事实证伪 | 参数、卖点或可验证能力被同一事实层证据明确否定，不属于普通主观负面。 |

## 5. 核心业务规则

### 5.1 购买理由成立与购买阻力分离

- 成立度只读取正向且与当前锚点同维度的证据。
- 普通 `comment_claim_contradiction` 不从成立度扣分，不删除锚点。
- `m12c_related_claim_negative` 不删除锚点，记录为市场/价值承接压力。
- 负面评价数量较多时，记录 `negative_dominant` 压力；只要正向成立证据仍满足门槛，购买理由仍存在。
- 事实证伪、评论错配、跨 SKU 证据污染或正向证据本身不成立时，才阻断理由成立。
- 同一理由允许同时是“核心购买理由”和“高购买阻力”。

### 5.2 压力标签

每个购买理由锚点至少支持以下压力类型：

| 压力类型 | 业务含义 | 是否否定理由成立 |
| --- | --- | --- |
| `localized_negative` | 局部方面存在负面体验 | 否 |
| `mixed_feedback` | 同一理由下正负评价并存 | 否 |
| `negative_dominant` | 同维度负面评价占主导 | 否；标高压力 |
| `m12c_value_headwind` | M12C 显示价值承接或价格压力 | 否 |
| `market_uncertainty` | 市场池或样本不足，比较结论受限 | 否；限制市场比较 |
| `objective_falsification` | 产品事实或能力被明确证伪 | 是 |
| `evidence_misalignment` | 评论、卖点或市场证据不属于当前锚点 | 是 |

压力必须包含中文解释、证据引用、影响方面、强度和是否限制比较，不向业务报告输出内部英文 code。

### 5.3 产品价值主张与用户购买理由分层

每个候选锚点必须标记以下状态之一：

| 状态 | 最低证据 | 可作为核心购买理由 |
| --- | --- | --- |
| `proposition_only` | 参数/事实卖点 + 语义场景 | 否 |
| `user_supported` | 同锚点用户正向感知 + 产品或场景事实 | 可进入分层兜底，需满足理由门槛 |
| `market_supported` | 市场承接 + 产品事实 + 场景 | 仅客观比较理由可进入分层兜底 |
| `user_validated` | 同锚点用户感知，并由市场或 M12C/选择证据交叉支持 | 是 |
| `rejected` | 证据错配、事实证伪或最低成立证据不足 | 否 |

“家庭操作更省心”和“新家家装更适配”不从 taxonomy 删除：

- 只有参数、卖点和场景时保留为 `proposition_only`。
- 出现同维度用户评论、选择表达或市场承接后，可升级为用户购买理由。
- `proposition_only` 可供产品经理查看“希望传达什么”，但报告必须说明“尚未观察到用户承接”。

### 5.4 分层成立门槛

- 标准强成立：正向成立分 `>= 9`，至少两个强证据域，场景成立。
- 无核心兜底：正向成立分 `>= 8`，只用于当前无核心 SKU；保留双强域、评论同锚点、价格和品类业务边界。
- 理由专属兜底：正向成立分 `>= 7`，必须通过理由自身边界，例如 TV 大屏理由的尺寸门槛、低价理由的价格带门槛；AC 使用独立规则。
- 不允许低于 7 分形成核心购买理由。
- `proposition_only` 不因分数达到 7/8/9 自动升级为用户购买理由。

### 5.5 SKU 与版本消费

- SKU 是否可消费，由该 SKU 的画像状态和具体维度决定。
- 版本覆盖率不足不得把版本内全部 `ready` SKU 统一降为 `published_degraded`。
- 有核心理由的 SKU 可进行购买理由强比较，并同时输出压力画像。
- 只有产品价值主张的 SKU 可比较参数、卖点、价值战场、市场和产品意图，但不能输出强购买理由替代结论。
- 没有核心理由不等于没有产品价值，也不等于全部竞品维度不可比较。
- 版本级状态只控制是否允许发布、是否需要审批和覆盖风险说明，不覆盖 SKU 级业务质量。
- 发布质量必须分开计算“强消费覆盖”和“至少一个业务维度可消费覆盖”：前者只统计 `ready`，后者统计 `ready + ready_limited + weak_expression_only`。
- `weak_expression_only` 不能进入强购买理由比较，但只要参数、卖点、市场等事实维度可用，就不得被发布质量算法计为整个 SKU 不可消费。
- `ready_or_limited_rate` 仅保留为诊断指标，不再作为 SKU 可消费覆盖的发布门槛。
- 候选 M12D 完全缺失、版本 blocked 或 SKU 不可消费时，不得依赖该候选进入 Top 3；`facts_only` 候选仍可凭参数、卖点、市场、价值战场、用户任务和目标客群参与，但购买理由重合贡献必须为 0。
- 每个 Top 3 候选必须说明购买理由重合和替代压力对排序的具体贡献；不得把版本级质量统一降级解释成该 SKU 的购买理由不成立。
- 业务输出必须把“已成立购买理由的重合”“竞品对本品的替代压力”“双方各自已成立理由上的购买阻力”分开，不得用一个压力字段混合表达。购买阻力不是竞品识别评分维度，不得在分析过程目录中设为独立比较章节；只有双方存在同一已成立理由且阻力均已评估时，才可在关键价值锚点或产品画像中作为“不计分”补充展示，否则整段省略，不输出占位表。

## 6. TV/AC 品类隔离

- TV 和 AC 分别配置 9/8/7 分层理由边界。
- TV 大屏、游戏、画质、家装规则不得进入 AC。
- AC 匹数、能效、舒适风、新风、静音和维护规则不得进入 TV。
- 同一共享压力类型可以复用 typed contract，但压力与锚点的映射来自本品类 taxonomy。
- 两个品类分别重跑、分别统计、分别审批和发布。

## 7. 输出契约要求

每个锚点新增或明确输出：

- `establishment_status`
- `establishment_score`
- `user_validation_status`
- `core_eligible`
- `proposition_evidence_json`
- `user_support_evidence_json`
- `pressure_level`
- `pressure_tags_json`
- `pressure_summary_cn`
- `comparison_limitations_json`

兼容字段 `role`、`evidence_strength`、`risk_flags_json` 和 `adjusted_evidence_score` 保留读取期，但不得继续承担混合语义。

历史版本缺少新字段时，成立状态、用户承接和压力等级统一读取为 `unassessed`，`core_eligible` 和成立分保持 `null`；不得把缺失猜成 `rejected`、`not_observed`、`none`、`false` 或 `0`。

## 8. 验收要求

### 8.1 业务正确性

- 普通负面评价不得删除已由正向证据成立的购买理由。
- 同一锚点可同时输出核心理由和高压力标签。
- 事实证伪和证据错配必须阻断核心理由。
- `proposition_only` 永远不能直接输出为“用户购买理由”。
- 家庭操作、家装适配在无用户承接时保留为产品价值主张。

### 8.2 数据正确性

- 评论必须按 SKU、锚点、维度和极性对齐。
- 负面压力必须保留原始评论或 M12C 证据引用。
- 不允许一个 claim/comment 的负面扩散到未引用该证据的锚点。
- 缺失仍为未知，不转成负面或不成立。

### 8.3 回归

- TV 至少覆盖 QF15A 的 139 个无核心 SKU、65E7Q、A7H PRO、华为重点样本和边界尺寸样本。
- AC 至少覆盖既有 18 个重点/边界样本及评论负向样本。
- 已有 `ready` SKU 的成立理由不得因新增压力字段无解释地改变。
- 竞品 Top 3 的变化必须能追溯到成立理由或压力，而不是版本统一降级。
- `proposition_only` 在竞品报告中统一表达为“产品希望传达但尚未观察到用户承接”，不得进入购买理由重合分。
- 替代压力低于强阈值时直接表达为较弱或参考竞品，不得同时使用“威胁”“最可能影响最终成交”等强结论。

## 9. 发布边界

- 本需求先通过 shadow 产物验证，不直接修改 current published。
- 提交部署和 205 正式全量发布分别设置人工确认任务。
- 若 TV 或 AC 任一品类出现大规模错误核心理由、跨品类串用或事实证伪未阻断，停止发布。
