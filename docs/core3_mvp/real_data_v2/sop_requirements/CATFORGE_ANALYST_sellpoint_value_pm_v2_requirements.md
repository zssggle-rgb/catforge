# 用户卖点价值分析智能体 V2（产品经理版）需求说明

## 1. 文档目的

本需求定义一个与现有 `sku-claim-value` 并行运行的新智能体 `sellpoint-value-pm`。它不回答“系统给卖点分了多少钱”，而是帮助产品经理判断：

1. 用户把本品的产品表达理解成了什么；
2. 哪些技术点只能合在一起形成一个用户价值，哪些可以单独判断；
3. 在现有市场数据中，该价值是否表现出同价选择优势；
4. 当前证据能否进入价格测试，以及应测试什么价格情景；
5. 既有竞品在同一价值上如何配置、如何被用户理解、市场承接如何；
6. 下一版产品应保留、补强、重写表达、组合测试，还是先补证据。

V2 不假设产品经理原始设计意图，只对“产品侧已发布事实/表达”和“用户及市场侧反馈”进行核对。

## 2. 业务问题与术语

### 2.1 产品经理首页必须回答的六个问题

| 业务问题 | V2 输出名称 | 允许的结论 |
| --- | --- | --- |
| 用户到底认到了什么 | 用户怎么理解 | 直接认到、只认到结果、尚未认到、出现反向体验 |
| 这个卖点在用户选择中有多重 | 同价选择优势 | 相对可比池的选择份额优势及可信等级 |
| 当前价格是否已经吃掉该优势 | 当前价格承接状态 | 留有空间、基本承接、承接过度、无法判断 |
| 大致可加到哪里仍保持原有选择水平 | 选择保持价差 | 区间或空值；必须同时给方法、样本和边界 |
| 不同价格会发生什么 | 价格情景 | 相对选择指数、相对收入指数，不承诺绝对销量 |
| 下一步做什么 | 产品动作 | 保留、补强、改用户语言、组合测试、单项测试、补证据 |

### 2.2 “卖点称重”的四个正交维度

V2 不产生一个混合总分。每个用户价值单元分别给出：

- 产品成立度：产品事实是否成立、是否存在画像冲突；
- 用户感知重量：有多少有效评论能直接或间接归因，分母是什么；
- 选购作用：明确选购理由、可能的入围门槛、购后满意、评价分化或尚未证明；历史整机销量承接不回填为单卖点数值；
- 定价准备度：现有证据是否足以进入单项测试、组合测试或暂不测试。

成本与利润数据不在当前范围，因此不输出利润重量、毛利贡献或利润最优价。

### 2.3 用户价值单元，而非逐参数强行计价

默认按用户可感知结果组合卖点：

| 价值单元 | 可包含的产品事实 | 用户结果示例 |
| --- | --- | --- |
| 明亮环境与明暗层次 | MiniLED、峰值亮度、分区控光、画质芯片 | 白天不发灰、暗场层次、光晕控制 |
| 游戏与运动流畅 | 刷新率、低延迟、HDMI 2.1、运动补偿 | 操作跟手、球赛/高速画面少拖影 |
| 色彩与画面真实 | 色域、色准、量子点、画质调校 | 肤色自然、颜色准确、画面通透 |
| 影院声场 | 扬声器、声道、杜比能力 | 对白清楚、声场包围、低频表现 |
| 系统与交互效率 | 芯片、内存、语音、投屏、互联 | 开机/切换流畅、投屏稳定、操作省事 |
| 长时间观看舒适 | 防反、低蓝光、无频闪、环境光调节 | 强光少反光、久看不累 |

只有当某技术点具备独立产品差异、独立用户表达或独立配置/价格变化时，才允许单独称重；否则必须保留在价值组合中，避免重复计价。

## 3. 数据复用范围

V2 只消费已发布画像，不另起底层数据链路：

| 模块 | 用途 | 使用边界 |
| --- | --- | --- |
| M03B 参数事实 | 判断能力、档位、证据与冲突 | 缺失是未知，不等于没有 |
| M04C 卖点事实 | 读取产品侧表达与事实匹配 | 与 M03B 冲突时触发降级，不能自动绕过 |
| M05C 评论事实原子 | 用户结果、正负体验、直接/间接归因 | 评论不是购买原因，也不是金额证据 |
| M07 市场画像及周度明细 | 价格、销量、同池位置、价格响应 | 只表述观测关联，不宣称因果 |
| M09C/M10C/M11C/M11D | 人群、任务、战场与市场语义 | 用于定义适用场景，不作为独立购买证明 |
| M12D 购买理由画像 | 形成待验证的选择理由假设 | 属于衍生判断，不与上游证据重复计数 |
| M14 竞品选择 | 直接竞品与角色 | V2 不重新选竞品，不复用竞品报告结论当证据 |
| M12C 现有卖点价值 | 可比池和基础市场事实 | 不复用角色、分摊金额或最终文案作为 V2 真值 |

版本一致性要求：`latest` 必须把独立生成的可用 M14 批次纳入 serving scope；M14 再锁定该范围内最新的 `success` 或 `limited` 选择运行，读取该运行的全部槽位，不能用旧运行补空位；显式历史批次不得读取未来 M14。评论原子和周度市场明细必须分别跟随每个 SKU 当前评论画像、市场画像所在的权威批次，不能跨导入批次拼接样本。

## 4. 量化口径

### 4.1 同价选择优势

含义：在相同尺寸、相近价格、相同周次和平台的观测池中，本品相对选择份额的优势。选择份额以销量占池内销量表示。

输出必须包含：

- `observed_share`：本品实际池内销量份额；
- `same_price_expected_share`：直接竞品条件选择曲线在相同成交价位置的预期份额；
- `same_price_choice_advantage`：相对两款五五开基准的百分点差；
- 有效竞品对数、重叠周平台单元、价差覆盖范围、组合隔离等级和可信等级；
- L0/L1/L2/L3 方法等级。

该指标属于整机/价值组合层面的市场信号。除非存在可靠反事实，不能分摊成单个技术点的金额。

### 4.2 选择保持价差

含义：按照本品在观测期内的局部价格响应估计，价格上调到何种幅度会消耗当前同价选择优势，使相对选择指数回到基准水平。

输出规则：

- 价格变动不足、有效周少于阈值、弹性方向异常或促销污染严重时返回空值；
- 只输出保守区间，不输出单点“卖点值 X 元”；
- 明确它是价格测试区间，不是建议售价，也不是用户愿付金额的直接测量；
- 只有组合具备选择优势且价格响应可识别时才允许计算。

首页另需给出“当前价格承接状态”：`仍有承接空间 / 价格已基本承接 / 价格可能承接过度 / 未观察到可承接优势 / 无法判断`。该状态必须由同一批直接竞品曲线上的同价位置与当前价位置共同支持，不能由评论声量或单个技术参数推断。

### 4.3 价格情景

至少展示当前价、`-5%`、`+5%` 三档；证据允许时可增加“选择保持价差上沿”。每档输出：

- 相对选择指数（当前价 = 100）；
- 对比销售额指数（当前价 = 100，固定对照规模，仅作方向观察）；
- 业务解释；
- 停止条件，例如选择指数跌破阈值或证据不足。

## 5. 证据状态与降级规则

### 5.1 用户证据状态

| 状态 | 业务语言 | 最低条件 |
| --- | --- | --- |
| E0 | 产品事实冲突 | 关键画像互相矛盾或产品事实不成立 |
| E1 | 产品有，但用户反馈未说明 | 产品事实成立，无可归因用户结果 |
| E2 | 用户认到体验结果 | 有有效直接/间接评论证据 |
| E3 | 市场选择出现优势 | 同池观测达到 L1/L2，结果方向稳定 |
| E4 | 可进入价格测试 | 同价优势、局部价格响应与样本门槛同时成立 |

### 5.2 评论归因

- 直接：评论明确提到技术名、参数、功能或唯一结果，例如“高刷打游戏不拖影”。
- 间接：评论只描述与价值单元一致的体验结果，例如“白天客厅画面不发灰”，可支撑组合但不能指定单一技术点。
- 不可归因：过于泛化，例如“画质很好”“很清晰”，只能计入总体画质，不能自动归到 MiniLED、5200nit 或分区数。
- 反向：评论描述负向体验或与产品主张矛盾，必须单列。

相同评论句在同一价值单元只计一次。服务、物流、安装履约评论不得进入商品价值称重。

### 5.3 跨画像一致性闸门

关键事实必须核对 M03B 与 M04C。出现以下任一情形时：

- M03B 有事实、M04C 却声明 M03B 缺失；
- 关键接口数量、刷新率、亮度、分区等互相冲突；
- 画像批次、规则版本或 SKU 不一致；
- 评论事实将泛化体验批量映射到具体技术卖点；

V2 必须在首页展示“数据需修复”，受影响价值单元最高停在 E1/E2，相关价格量化置空。其余不受影响价值单元可以继续分析。

## 6. 竞品边界

V2 必须引入竞品对照，但不能成为第二份竞品分析报告：

1. 直接复用 M14 已选 1–3 款竞品及其角色；
2. 若 M14 不可用，允许回退到现有 `competitor-set`，并标记来源和降级；
3. 每个价值单元只展示“本品事实—竞品事实—用户反馈—市场结果—动作”；
4. 不重算竞品排名，不复制竞品报告长结论；
5. 提供既有竞品报告入口（存在时），详细竞品策略留在原智能体。
6. 标杆、上探、下探和情景参照竞品只用于事实校准；只有既有竞品角色明确为直接对打、量价压力或近价直接对照时，才允许进入当前同价价格曲线。
7. M14 原生只有两类可进入价格曲线的角色，因此稳定价格等级以“两类对照均为强样本且方向一致”为门槛；不得为了凑第三对把标杆竞品塞入当前价格曲线。

## 7. 产品经理报告信息架构

报告顺序固定：

1. 本周可做的产品决策：3–5 条具体动作；
2. 卖点称重总表：一行一个价值单元；
3. 价格承接与情景：整机/价值组合层；
4. 每个价值单元的“产品怎么说、用户怎么说、竞品怎么做、市场怎么接”；
5. 数据问题与不能下的结论；
6. 下一步测试清单：对象、对照、价格档、目标人群、成功/停止条件；
7. 证据附录：样本、批次、规则版本、证据 ID。

业务页面不得出现“价值棒”“WTP”“消费者剩余”等术语；内部字段可保留方法编码。

## 8. 65E7Q 最低验收场景

海信 65E7Q 必须至少形成以下价值单元：

- 明亮环境与明暗层次；
- 游戏与运动流畅；
- 色彩与画面真实；
- 影院声场；
- 系统与交互效率；
- 长时间观看舒适。

验收必须证明：

- “画质清晰”不会被直接算成 MiniLED、5200nit、1920 分区三份证据；
- M04C 与 M03B 的已知冲突会显示并阻断受影响单元的价格量化；
- 300Hz 只有泛化“游戏性能”评论时，不会输出独立金额；
- 芯片若只被系统流畅评论支持，不会自动支撑 AI 画质价值；
- 竞品来自既有集合，V2 不另选竞品；
- 数据不足时合法输出“暂不计算选择保持价差”，并给出可执行补证据动作。
- 有产品事实冲突时，卡片必须将相关组合只放入“暂停判断”，不得同时列入“用户已接住”或“有配置未接住”；若全部受影响，必须显示受影响总数。

## 9. 非功能与边界要求

- 旧版 `sku-claim-value` 行为与输出契约保持不变；
- 新公共函数使用类型化输入输出，测试不调用外部 LLM；
- 每项分析保留 `category_code/project_id/version/batch_id/evidence_ids/confidence/review_status`；
- 生成报告可选 `none/markdown/feishu-doc`，发布失败时保留本地 Markdown；
- 缺失值保持未知，不能转为否定；
- 所有数值结论可追溯到输入样本与方法等级；
- 任何单项金额不得由整机价差按权重分摊生成。

3. 65E7Q 本地输出通过业务规则断言；
4. 代码仅提交本任务文件；
5. 部署 205 后用真实 65E7Q 生成 JSON、Markdown 和飞书文档；
6. 回读飞书文档，确认结构、数字、证据边界和产品经理语言一致。
