# M12D SKU成交理由画像需求

## 1. 模块定位

M12D 是独立的 SKU 级业务资产生产模块，用来回答“一个 SKU 凭什么成交、哪些价值锚点真正支撑用户选择、哪些只是宣传表达或弱信号”。

M12D 不属于竞品分析智能体的内部步骤。它必须先完成分析、设计、实现、小批量验证和全量结果生成，再由竞品分析智能体、卖点价值分析、产品百科或其他下游能力消费。

M12D 的核心产出是 `SKU成交理由画像`，不是 pair 级竞品判断，也不是“每个 SKU 独有标签”。同一价值锚点可以被多个 SKU 共享；竞品分析只在 M12D 结果之上判断目标 SKU 的核心成交理由是否被候选 SKU 覆盖、替代或强化。

## 2. 解决的问题

当前竞品分析里的“关键价值锚点”更多来自 pair 评分时临时拼接参数、卖点或位置标签，存在三个问题：

1. 没有先判断单个 SKU 自身的成交理由是否成立。
2. 容易把 `value_price`、`price_value`、厂家主张或弱表达写成强成交理由。
3. 下游业务报告无法解释“为什么这个 SKU 的成交理由是这些、证据强到什么程度、哪些只是待验证”。

M12D 必须把这些判断前置成可复用、可审计、可批量生成的 SKU 级资产。

## 3. 上游输入

M12D 消费当前真实数据链路中已发布的事实、语义和市场资产，不直接读取原始四张表做最终结论。

| 输入 | 用途 |
| --- | --- |
| M03B SKU 参数事实画像 | 判断价值锚点是否有硬参数支撑、强弱档位和缺口。 |
| M04C SKU 卖点事实画像 | 获取标准卖点、厂家表达、参数支撑等级、同源同参分组和输入门槛。 |
| M05C SKU 评论事实画像 | 判断用户是否感知该价值，以及正负向反馈和冲突信号。 |
| M07 SKU 市场画像 | 获取尺寸、价格带、均价、周均销量、销额、平台和观察窗口。 |
| M09C 用户任务画像 | 判断价值锚点服务哪些购买任务。 |
| M10C 目标客群画像 | 判断价值锚点服务哪些人群。 |
| M11C 价值战场画像 | 判断 SKU 落在哪些主/辅/机会/拖后腿战场。 |
| M11D 语义市场图谱 | 获取战场、任务、客群的空间和销量分配权重。 |
| M12C 用户卖点支付价值 | 判断卖点是否形成高溢价、份额转化、客户获得价值、门槛、待激活、竞品拦截或价格压力。 |

如果 M12C 缺失，M12D 可以生成降级画像，但必须降低置信度，并把相关锚点标为 `weak_expression`、`supporting` 或 `insufficient`，不得强判 `core_payment`。

## 4. 核心业务定义

| 术语 | 定义 |
| --- | --- |
| SKU成交理由画像 | 单个 SKU 的核心成交理由、关键价值锚点、证据强度、置信度和风险标记。 |
| 标准价值主题 | 用户可感知的价值类型，例如画质升级感、动态画面稳定感、预算配置效率；它只解释用户获得什么价值，不直接等同购买理由。 |
| 标准购买理由 | 用户为什么选择这个 SKU 的决策解释，例如贵得值的体验升级、同价位核心配置获得感、游戏设备适配降低踩坑风险。 |
| 关键价值锚点 | M12D 最终画像中的可消费解释单元，必须由标准购买理由生成，并关联一个或多个标准价值主题。 |
| 核心成交理由 | 能解释本 SKU 为什么会被用户选择或承接高价的 1-3 个业务理由。 |
| `core_payment` | 核心支付理由，必须有强证据支撑。 |
| `supporting` | 辅助成交理由，能增强选择，但不单独支撑核心成交判断。 |
| `weak_expression` | 弱表达，主要来自厂家主张、位置标签、泛化性价比表达或证据不足。 |
| `risk_drag` | 拖累理由，评论、参数、市场或语义信号削弱成交。 |

命名约束：

- 模块和资产名使用 `SKU成交理由画像`。
- 画像内部字段使用 `关键价值锚点`。
- 下游竞品分析维度使用 `关键价值锚点可替代性`。
- pair 级结论可表达为 `成交理由替代强度`。

## 5. 画像输出要求

每个 SKU 必须输出以下结构化结果：

| 输出 | 要求 |
| --- | --- |
| 基础信息 | `category_code`、`project_id`、`version`、`batch_id`、`sku_code`、品牌型号、生成时间和画像版本。 |
| 核心成交理由 | 最多 3 条，必须是业务语言，不能是参数清单。 |
| 关键价值锚点列表 | 每个锚点包含锚点 code、中文名、角色、证据强度、证据域、置信度和解释。 |
| 证据摘要 | 参数、卖点、评论、M12C、战场、任务、客群、市场承接的摘要。 |
| 弱表达与拖累 | 标注厂家主张、价格价值表达、评论负向、样本不足、市场未承接等风险。 |
| 下游消费字段 | 提供给竞品分析的 `core_payment_anchors`、`supporting_anchors`、`weak_expression_anchors`、`risk_drag_anchors`。 |

输出不得包含内部 SQL、原始 JSON、未翻译 code 或调试字段。技术追溯可以保留在审计字段中，但业务报告默认不展示。

## 6. 证据强度规则

| 证据强度 | 判定口径 |
| --- | --- |
| `strong` | 至少两个证据域支撑，且包含参数事实、M12C 支付价值、评论感知或市场承接中的强证据。 |
| `medium` | 一个强证据域加一个辅助证据域，或多个中等证据共同支撑。 |
| `weak` | 主要来自厂家表达、位置标签、泛参数表达、样本不足或缺少用户/市场验证。 |
| `insufficient` | 数据不足或证据冲突，不能形成正向成交理由。 |

硬规则：

1. 只有 `value_price`、`price_value`、价格价值表达、厂家主张或位置标签时，不得输出 `core_payment`。
2. 服务履约、物流安装、售后、权益、补贴只可作为风险或购买辅助，不得进入产品核心成交理由。
3. 宽泛卖点必须拆到可验证的产品能力或场景理由，不能把“高端画质”“智能体验好”直接当作强证据。
4. 评论负向和市场未承接必须降低锚点角色或置信度。

## 7. 首版电视标准价值主题和购买理由

### 7.1 标准价值主题

| 价值主题 | 示例 |
| --- | --- |
| 画质升级感 | 清晰度、亮度、控光、色彩和显示技术升级。 |
| 动态画面稳定感 | 游戏、体育、运动画面流畅、低延迟、少拖影。 |
| 客厅沉浸感 | 大屏、音效、杜比、观影距离和客厅空间。 |
| 预算配置效率 | 给定预算和尺寸池里的核心配置、价格和销量承接效率。 |
| 长看舒适感 | 护眼、低蓝光、无频闪、抗反光和家庭长时间观看。 |
| 操作便利感 | AI、语音、投屏、IoT 和系统易用。 |
| 空间审美适配 | 外观、超薄、贴墙、全面屏、壁画和新家装修。 |

### 7.2 标准购买理由

| 购买理由 | 示例 |
| --- | --- |
| 画质配置解释加价 | 用画质事实和用户感知解释更高价格。 |
| 贵得值的体验升级 | 虽然更贵，但多花的钱换来明确体验升级。 |
| 同价位核心配置获得感 | 同尺寸/同价位池里提供更可解释的核心配置获得感。 |
| 游戏设备适配降低踩坑风险 | 高刷、接口、低延迟和游戏场景证据降低买错风险。 |
| 客厅换新一步到位 | 尺寸、画质、观影任务和市场承接共同支持换新选择。 |

价值主题和购买理由可以随品类扩展。空调、冰箱、洗衣机等品类必须维护独立配置，不得复用电视 taxonomy 强行解释。

## 8. 批量生产与验证流程

M12D 必须按独立模块节奏推进：

1. 分析阶段：抽样查看 65E7Q、65A7H PRO、65Q9L PRO、小米 L65MC-SP 等 SKU 的上游证据，确认锚点规则和弱表达边界。
2. 需求与设计阶段：形成 M12D 需求、详细设计、输出 schema、评分规则和验证集。
3. 实现阶段：实现画像生成服务、CLI、存储和测试。
4. 小批量验证阶段：先跑 10-20 个高关注 SKU，人工检查成交理由、弱表达、证据强度和置信度。
5. 全量生成阶段：对当前 TV batch 全量 SKU 生成 M12D 结果，记录批次、版本和失败清单。
6. 发布阶段：标记可被下游消费的 M12D 版本，并输出质量报告。
7. 下游验收阶段：竞品分析智能体只消费已发布 M12D，不在问答时临时生成。

## 9. 与竞品分析智能体的边界

M12D 负责：

- 生成单 SKU 的成交理由画像。
- 判断单 SKU 内部的关键价值锚点、证据强度和风险。
- 发布可复用、可审计、可批量刷新的画像资产。

竞品分析智能体负责：

- 读取目标 SKU 和候选 SKU 的已发布 M12D。
- 在 pair 级计算关键价值锚点可替代性。
- 在竞品报告中展示目标与 Top 3 的成交理由差异。
- 当 M12D 缺失或版本不可用时降级或阻断，不负责补跑 M12D。

## 10. 验收标准

- 能为每个 TV SKU 生成 `SKU成交理由画像`，且包含核心理由、锚点角色、证据强度、置信度和风险标记。
- 65E7Q 的价格价值表达只能作为弱表达，不能直接成为强核心成交理由。
- 小批量验证中，业务人员能看懂“为什么这些是成交理由、哪些证据强、哪些证据弱”。
- 全量 TV batch 生成后，有成功数、失败数、低置信画像数和需复核画像清单。
- 竞品分析智能体能读取 M12D 结果，但不在自身流程里生成 M12D。
