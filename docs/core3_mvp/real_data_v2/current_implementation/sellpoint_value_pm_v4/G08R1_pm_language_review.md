# G08R1 产品经理业务语言复审

## 结论

`PASS`。主表现在能够把“用户价值是否成立”和“市场量价能量化到哪一步”分开表达，并修复了纯负向体验、市场范围缺失和重复表述问题。

## 产品经理看到的业务账

每一行仍固定回答七个产品问题：

1. 这笔价值属于哪个战场，市场空间口径是什么；
2. 本品为什么进入用户选择；
3. 用户购后实际获得了什么；
4. 哪些配置和卖点必须组合解释；
5. 相对基础价值和同价值竞品处于什么位置；
6. 当前最多观察到价值成立、选择关联、整机价格承接还是严格市场隐含区间；
7. 该组合在 SKU 中属于什么产品角色。

市场空间单元格现在同时显示：目标尺寸档、观察窗口、实际平台覆盖和已有市场空间数值。例如：

> 高端画质升级战场（65-75 英寸档、完整观察期、jd+tmall 平台；估算销量约 1,000 台）

这避免产品经理把 1,000 台误解为全品类、全尺寸或未知时间范围的市场规模。

## 用户体验状态

| 数据状态 | PM 文案 | 业务含义 |
| --- | --- | --- |
| established | 用户已实际感知到这项价值 | 产品能力在购后形成了预期好处 |
| partial | 用户只感知到部分价值 | 只有部分结果成立 |
| negative | 用户实际获得的是负向体验 | 产品具备能力，但价值没有兑现 |
| mixed | 不同用户或场景体验分化 | 体验正反并存，不能写成稳定兑现 |
| not_observed | 现有证据尚未观察到 | 不能把产品具备直接写成用户价值 |
| lineage conflict | 事实版本冲突，当前不能判断 | 数据问题，不冒充用户体验分化 |

negative、mixed 和 data conflict 的 JSON、短答、Markdown、飞书卡片均来自同一 report object，且不能进入金额。

## 业务语言门禁

- 主表无 Mxx、Qx、isolation grade、SQL、evidence ID、relation hash 或英文 error code；
- 不推测购买前传播心智；
- 不生成建议涨价/降价/增配/减配或下一步工作清单；
- 无法量化不写成价值为零；
- 共线卖点只按组合显示金额边界；
- 市场隐含区间明确写“市场关联，不是心理最高价”；
- “用户已实际感知到这项价值：用户购后反馈已观察到”已压缩为一次结论和一次具体体验；
- 双链接继续分别为“查看用户选择对比”和“查看分析依据”。
