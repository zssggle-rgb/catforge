`latest` 可能由多个真实来源批次组成。RC 将它拆成“完整读取范围”和“真实持久化锚点”：所有上游读取使用完整服务范围，画像外键使用范围中的首个真实批次，全部来源批次保存在版本 `source_scope_json`。报告按 `latest` 读取时映射回相同锚点，不把服务范围字符串写入数据库外键。

## 产品决策口径

- 基础门槛：至少达到品类配置的已知样本数和普及率门槛；缺失和冲突样本不计入“已知没有”。
- 值得保留：用户体验形成相对优势，且当前价格、销量或选择表现至少一项支持，同时没有反向市场信号。
- 投入未转化：本品已具备高投入能力，但用户兑现偏弱、未观察到或弱于对照产品。
- 不必跟进：本品已知缺少该配置、对照产品普遍具备，但本品当前销量/选择表现并未更弱。
- 竞争缺口：本品已知缺少该配置、对照产品普遍具备，且本品当前销量/选择表现更弱。
- 未知：事实缺失、来源冲突、比较范围不完整或样本不足时，不进入确定取舍。

这些结论是当前市场关联判断，不把单卖点写成实验因果。画像同时保存候选范围、量价比较、来源 hash、真实记录 ID、证据 ID、置信度和复核状态，供报告解释与深入问答。

## G08 审查发现与修复

| 级别 | 发现 | 修复与验证 |
|---|---|---|
| P0 | 生命周期只有测试输入桩，没有生产数据提供器和 205 可调用生成命令 | 新增真实输入组装器、单 SKU/批量 CLI、显式写入开关及端到端生命周期测试 |
| P0 | 空版本或仅生成一个 SKU 的版本可能被错误推进发布 | 发布前强制核对权威 SKU 数、实际画像数、四类状态计数和处理状态 |
| P0 | 并发创建版本/写同一 SKU 可能触发唯一键竞态 | 使用保存点复用相同不可变结果；不同 hash 继续拒绝 |
| P0 | 保存点在 SQLite 延迟事务下可能导致 hash 校验失败后草稿残留 | 单 SKU和批量均先写外层版本进度，再进入保存点；两种回滚测试均为零残留 |
| P1 | 两个版本并发发布可能争夺同一 current 槽位 | 先锁来源批次共享发布槽位，再锁目标版本，避免锁顺序死锁 |
| P1 | `latest` 组合批次不能写入外键 | 分离来源读取范围与真实持久化锚点，并补组合范围读取回归 |
| P1 | 市场参照缺少真实 hash 时曾生成占位 hash | 删除占位 hash；没有真实 hash 就保持未知 |
| P1 | 候选来源曾用“SKU:模块”作为记录标识 | 保存 M12/M13/M14 真实记录 ID、证据 ID及 M12 特征快照来源 |
| P1 | 批量失败提示要求查日志但未记录异常 | 增加服务端结构化异常日志，对 CLI 仍只返回脱敏错误 |
| P1 | 无权威 M07 SKU 也可能通过单 SKU入口写草稿 | 在创建版本和加载输入之前拒绝范围外 SKU |
| P1 | naive 时间戳受服务器时区影响 | 明确按 UTC 解释并转换为 Asia/Shanghai 展示 |

预落地复核后，任务范围内没有遗留 P0/P1。
