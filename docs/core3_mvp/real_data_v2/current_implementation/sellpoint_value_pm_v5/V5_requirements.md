# 用户卖点价值分析 V5 修改需求

状态：G00 冻结候选

日期：2026-07-11

2026-07-13 补充：候选竞品、门槛功能过滤、画像持久化、报告消费和深入问答的新需求见 `V5_profile_requirements_addendum.md`；与本文及 G08 内存门禁冲突时，以该补充需求为准。

前序基线：V4 默认关闭影子版本

交付对象：产品经理

运行边界：与 V2/V4 平行，只读、默认关闭

## 1. 产品定义

V5 要把一个 SKU 的配置、宣传卖点、用户反馈和市场量价，转成产品经理能直接用于产品复盘的一笔“用户价值账”：

> 用户实际感知到了什么价值；这些价值里哪些只是具备、哪些形成了相对亮点、哪些影响了市场选择；当前价格是否承接、销量是否承接；如果用市场中的可比方案作为反事实，没有这组价值时市场基线是什么，卖得好的组合和卖得不好的组合分别是什么；继续增强已有价值战场，还是拓展一个尚未进入的新战场，可能改变什么。

这不是评论摘要，也不是卖点自证报告。产品经理拿到结果后应能用于：

1. 判断哪些产品投入已形成用户可感知价值；
2. 找到相对同档方案真正成立的亮点，而不是所有 SKU 都成立的口水结论；
3. 判断亮点主要兑现为价格、销量、两者兼有，还是尚未被市场承接；
4. 参照市场中高绩效与低绩效价值组合，比较产品结构改进方向；
5. 区分已有战场增强与真正的新战场拓展，比较机会空间、实现路径和内部挤占；
6. 明确结论当前能量化到哪一层，避免把市场相关性冒充因果或用户心理最高价。

## 2. 核心业务问题

针对目标 SKU，V5 必须依次回答：

1. **用户感知价值是什么**：用户购买并使用后实际获得了哪些结果、便利或风险；产品具备的能力与用户感知的价值如何连接。
2. **什么构成亮点**：与同预算、同尺寸、同品牌梯度、同价值战场和市场基线相比，本品在哪些价值上更强且得到用户或市场兑现。
3. **没有这组价值会怎样**：在可控市场单元内构造“无此价值/较弱价值”的合成基线，比较价格、销量和份额的差异区间。
4. **好的组合与不好的组合是什么样**：识别同市场条件下高绩效、低绩效价值组合原型，说明差异来自哪些共同出现的能力和用户结果。
5. **价格和销量如何兑现**：分别输出价格承接、销量承接和整机量价位置；不得合成一个含糊的“高价值”标签。
6. **战场组合怎么优化**：对已进入的主、辅、机会、用户已观察战场判断增强方式；只对当前 excluded 且能力可达的战场讨论新拓展。
7. **结论能说到哪一步**：分别标记价值成立、相对优势、选择关联、价格承接、观察性增量、严格支付意愿识别状态。

## 3. 关键概念

### 3.1 产品能力、卖点、用户感知价值

- 产品能力：可验证的参数、配置和功能事实。
- 卖点：产品侧把能力组织成的市场表达。
- 用户感知价值：当前已有评论和体验事实中，用户实际获得的场景结果、便利、改善或风险。

卖点是用户价值的产品侧来源，不等于用户价值。用户没有说出技术名不代表没有感知价值；但“画面清晰”不能被拆分为高亮、分区、MiniLED 和画质芯片四项分别兑现。

V5 不推断现有数据无法支持的购买前传播心智，不把产品侧主张冒充产品经理确认过的设计假设。

### 3.2 价值成立与价值可量化

两者必须独立：

- `value_status`：用户价值是否观察到、部分观察到、正负并存、负向、冲突或未知；
- `quantification_status`：当前只能说明事实、相对差异、市场选择关联、整机价格承接、观察性销量增量，还是通过严格门禁的价值组合支付意愿区间。

有价值不等于可量化，可量化不等于可因果归因，可观察到市场承接也不等于应该涨价或增配。

### 3.3 价值组合

默认以共同产生同一用户结果的能力组合为分析对象。只有在市场中存在足够独立变化时才拆成单项卖点。

例如：

```text
高亮 + 分区控光 + MiniLED + 画质处理
  -> 强光清晰、暗场层次、光晕控制
  -> 画质升级价值组合
```

### 3.4 价值战场状态

主战场、辅战场、机会战场和用户已观察战场都属于目标 SKU 已经进入的战场，只是参与强度和产品角色不同。V5 不把它们写成“待进入的新战场”。

- 已有战场增强：在当前已进入战场内提高沟通激活、能力完整度、市场激活或组合优先级；
- 新战场拓展：仅针对当前 excluded 的战场，且必须证明任务/客群相邻、能力缺口可补、市场空间真实、不会只靠改名进入；
- 战场组合优化：比较已有战场增强和新战场拓展的空间、难度、证据、量价潜力与内部挤占。

## 4. 多层反事实体系

V5 不要求每个 SKU 都找到“唯一、只差一个卖点”的直接竞品。反事实按业务问题和证据强度分层，允许从直接对照降级到市场合成对照，但不得越级表述。

| 反事实 | 主要回答 | 最低控制条件 | 允许结论 |
| --- | --- | --- | --- |
| 直接 SKU 基础/同价值/上探 | 同一购买池内价值档位差异 | 尺寸、战场、时间、平台、价格重叠和主要配置 | 相对体验、选择和严格门禁下的组合金额 |
| 同预算替代池 | 用户相同预算还能买什么 | 同尺寸/形态、价格窗口、共同在售 | 本品在真实选择集中的相对价值与量价位置 |
| 同品牌同尺寸梯度 | 品牌内部升级由什么承接 | 同品牌、同尺寸、相邻价格层 | 版本梯度的配置、价值和量价差异 |
| 参数档位对照 | 某能力从基础到增强是否伴随市场差异 | 同市场池、档位可识别、控制其他主要能力 | 档位关联，不能自动归为单项因果 |
| 同宣称不同用户兑现 | 都在宣传时谁真正被用户感知 | 同价值表达、评论口径可比 | 宣称兑现差异与表达/体验错位 |
| 自身价格曲线 | 本品价格变化时销量如何响应 | 足够周数、平台、价格变化、异常过滤 | 整机价格敏感性和观察区间 |
| 市场合成基线 | 若没有/较弱这组价值，市场基线如何 | 同尺寸、预算、战场、周、平台；控制品牌层级和其他配置 | 观察性量价增量区间，非因果 |
| 高/低绩效组合原型 | 市场里卖得好/差的价值组合长什么样 | 对基础量价、周平台等控制后的残差绩效 | 组合参照，不给单项因果金额 |

反事实选择遵循：直接证据优先、市场合成补覆盖、每项结论绑定来源和限制、缺少高等级对照不等于没有亮点。

## 5. 市场合成对照

### 5.1 “没有这组价值”的市场基线

在同一市场单元中，从没有该组合或价值档位更低的 SKU 构造加权合成对照。至少控制：

- 尺寸/产品形态；
- 价格区间与品牌层级；
- 价值战场；
- 周、平台/渠道和共同在售；
- 其他核心配置和价值组合；
- 促销疑似、异常价和活跃周；
- 可用时的系列关系。

输出权重、平衡诊断、重叠范围、安慰剂/留一敏感性和不可用原因。它估计的是历史市场中的观察性差异，不是“增加该卖点必然多卖多少”。

### 5.2 高绩效与低绩效组合原型

先对周销量、销额或份额做基础条件校正，再以残差绩效识别高、低绩效组，至少控制尺寸、价格、品牌层级、活跃周、周×平台和促销疑似。

每个原型输出：

- 共同出现的价值组合及档位；
- 用户感知结果和风险；
- 典型价格、销量、份额和残差绩效区间；
- 与目标 SKU 的缺口；
- 样本数、稳定性与共线限制。

不得把“高绩效组中常见”改写为“该卖点导致高销量”。

## 6. 可量化结果与边界

### 6.1 允许输出

| 量化对象 | 允许指标 | 业务含义 |
| --- | --- | --- |
| 当前战场空间 | M11D 战场估算销量、销额、价格结构 | 战场规模与当前竞争空间 |
| 本品战场分配 | M11D 本品估算战场销量/销额及占比 | 将既有销量按语义分配到战场，不是增量 |
| 价值相对强度 | 用户结果、参数档位、同宣称兑现差异 | 本品价值是否形成相对亮点 |
| 市场选择关联 | 同价/近同价份额差、相对价差曲线 | 价值组合与选择表现的关联 |
| 整机价格承接 | 相对直接对照、同预算池和自身曲线 | 当前整套方案的价格位置与承接 |
| 合成对照销量差 | 周销量、份额、销额的观察性差异区间 | 历史市场中相似条件下的总销量差异 |
| 严格价值组合价格区间 | 仅在独立变化和稳定门禁通过时 | 历史市场隐含支付意愿估计 |
| 战场增强/拓展空间 | 市场空间、当前分配、可达差距、观察性量价区间 | 方案比较，不是确定销量承诺 |

### 6.2 战场销量的三笔账

必须分开：

1. **现有销量战场分配**：M11D 对本品既有销量的语义分配；各战场相加不应制造新增总销量。
2. **战场内部结构转移**：增强某战场后，可能改变各战场承接份额；属于组合重分配。
3. **净新增总销量**：只有合成对照、准实验或实验设计支持时才给观察性/因果区间；必须扣除内部挤占后才称净新增。

### 6.3 内部挤占

已有战场增强和新战场拓展都必须展示与本品现有战场、同系列 SKU 的重叠。若数据只支持重叠风险，不支持数量，则输出“挤占风险未知/低/中/高”，不得填造净新增数。

### 6.4 严格金额门禁

内部可保留 WTP 方法名用于审计，产品经理主报告统一表达为“价值组合的市场价格承接区间”。只有同时满足基础反事实、独立档位变化、有效价格与选择变化、非完全共线、共同市场覆盖、方向稳定、非外推和敏感性一致时才输出。

不满足时金额必须为空，并说明当前能支持到哪一层。

## 7. 产品经理输出合同

报告名：`{SKU} 用户感知价值与市场兑现`。

### 7.1 第一屏：产品经理现在能用的结论

固定回答四件事：

1. 本品最值得保留关注的 1—3 个用户价值亮点；没有相对亮点时明确写“当前未识别出可证实的相对亮点”；
2. 价格承接与销量承接分别如何；
3. 当前最值得比较的已有战场增强方案；
4. 是否存在真实、可达的 excluded 新战场拓展候选。

亮点必须至少满足以下一种，并明确是哪一种：

- 用户兑现亮点：用户获得了具体结果，且不是泛化技术映射；
- 相对价值亮点：相对同预算/同档/同宣称方案更强；
- 市场承接亮点：控制基础条件后价格或销量表现更好。

禁止为了版式强行生成亮点。

### 7.2 第二屏：用户价值账

一行一个“价值战场 × 用户价值组合”，不按孤立参数列行：

| 用户价值 | 用户实际怎么感知 | 哪些卖点共同形成 | 相对市场是什么位置 | 价格承接 | 销量承接 | 当前结论边界 |
| --- | --- | --- | --- | --- | --- | --- |

该表的作用是让产品经理逐笔核对：投入形成了什么用户结果、相对优势是否成立、最后由价格还是销量承接，而不是给算法自证。

### 7.3 第三屏：市场参照

固定展示：

- “没有/较弱这组价值”的市场合成基线；
- 高绩效价值组合原型；
- 低绩效价值组合原型；
- 目标 SKU 与三者的关键差异；
- 可比范围、样本和限制。

### 7.4 第四屏：价值战场组合优化

分两栏：

| 已有战场增强 | 新战场拓展 |
| --- | --- |
| 面向主、辅、机会、用户已观察战场 | 只面向当前 excluded 战场 |
| 判断沟通激活、能力补全、市场激活、组合优先级 | 判断任务相邻、能力缺口、市场空间、可达性 |
| 输出现有分配、可提升空间、量价参照、挤占 | 输出进入条件、观察性空间、难度、挤占 |

产品经理可比较方案，但 V5 不自动下达增配、减配、涨价或降价命令。

### 7.5 下钻与审计

产品经理下钻显示代表性用户原话、对照 SKU/合成池、时间和平台范围、主要差异与限制。内部模块码、SQL、模型变量、证据 ID 和英文状态码只进入 QA 附录。

JSON、短答、Markdown、飞书文档和卡片必须消费同一业务 DTO；渲染器不得自行推导新结论。

## 8. 功能要求

- F01：唯一解析 SKU/型号，锁定权威来源、市场窗口、版本和 lineage；冲突不静默择优。
- F02：读取 M03B/M04C/M05C/M07/M09C/M10C/M11C/M11D/M12D 和可用竞品事实，不重跑上游。
- F03：生成“用户价值—卖点组合”连接；泛化体验不拆给具体技术。
- F04：逐价值输出 value status 与 quantification status，两轴不得合并。
- F05：构建多层反事实并记录召回来源、角色、可比性、拒绝原因和降级路径。
- F06：生成同预算、同品牌梯度、参数档位、同宣称兑现、自身价格曲线和市场合成基线。
- F07：对市场合成对照执行平衡、重叠、留一和安慰剂诊断；失败时不输出增量。
- F08：生成控制基础条件后的高/低绩效组合原型，不进行单项因果归因。
- F09：分别计算价格承接、销量承接、当前战场分配、观察性总销量差和严格金额状态。
- F10：区分已有战场增强与 excluded 新战场拓展，输出路径、空间、难度、证据和挤占。
- F11：从真实数据中召回亮点；亮点为空是合法结果，通用结论不是亮点。
- F12：输出 PM DTO、短答、Markdown、飞书文档与双链接卡片，并与 V2/V4 平行。
- F13：所有结果包含 category、project、batch/version、market window、confidence、evidence refs、input/result hash。
- F14：默认关闭；未显式开启时不得执行 V5 查询，不改变自然语言默认路由。

## 9. 明确不做

- 不推断购买前传播心智或产品经理未确认的设计意图；
- 不用评论条数计算货币价值；
- 不把 M11D 战场分配销量写成新增销量；
- 不把相关性、合成对照或残差高绩效写成确定因果；
- 不把整机价差按评分分摊给卖点；
- 不给高度共线的单项能力分别计算金额；
- 不使用 M12C 旧金额作为真值、标签或回填；
- 不在没有成本时输出利润、价值捕获或投入回报；
- 不自动生成通用下一步工作清单；
- 不强行生成正向亮点；
- 不修改 M11C/M11D/M12D 生产合同；
- 不在本任务链切换默认自然语言路由。

## 11. 完成定义

V5 只有同时满足以下条件才算开发完成：

1. 需求、详细设计、验收矩阵和 Goal 调度均已独立提交；
2. 每类反事实在真实 cohort 有可用或正确降级样本；
3. 市场合成基线、高/低绩效组合通过确定性与敏感性测试；
