## 6. 本 Goal 修复的全量性能问题

全量执行中发现并修复了两处真实 P1：

1. 旧 V5 通用读取会装载画像首屏、问答索引和重复证据；重型价值项的 `investment_decisions_json` 达 9.34 MB，而 V5.1 实际只使用其中 6 个投资字段；
2. 每生成一个子批，旧进度更新都会重新完整反序列化并验算此前所有 SKU，导致完成数量越多，耗时和内存越大。

修复后：

- 旧 V5 输入改为强类型轻量投影，在数据库侧删除未使用的重复证据；
- 生成进度只读 SKU 状态小字段；
- 完整 hash、持久化投影和悬空引用校验只在全量结束后流式执行一次；
- 重型 SKU 的只读组装与 materialize 实测约 0.9 秒、233.6 MB；
- 稳定生成期间容器总内存约 600～650 MB，而修复前单个重型 SKU 曾达到 1.72 GiB；
- TV 和 AC 最终审计均未 OOM，API 重启数为 0。
