上位需求：`../sellpoint_value_pm_v5/V5_profile_requirements_addendum.md`

任务调度：`SPV_V5_1_goal_dispatch.md`

## 1. 本次重构要解决什么

V5 已经能保存用户价值、卖点投入、市场量价和产品经理决策，但 205 草稿尚不能正式使用，根因不是“没有分析内容”，而是两组结构性问题：

1. 正式竞品仍依赖旧 M12/M13/M14。TV 大量 SKU、AC 全量 SKU 因旧竞品上游不完整，只能退化为同尺寸市场参考；
2. 局部证据不足被逐级放大。一个候选缺 M13、一个投入无法分类、一个严格合成对照未通过，就可能把价值项、SKU 乃至整版画像标成 `review_required` 或 `blocked`。

V5.1 的目标不是删除证据边界，而是让系统尽量回答已经有数据支撑的问题：

> 有什么证据就回答到什么层级；某一问题没有证据，只让该问题无结论，不影响其他问题、其他价值和整版画像使用。

## 2. 产品目标

对每个 SKU 形成一份可正式消费的“用户卖点价值账”，稳定回答：

1. 用户实际感知到了哪些价值；
2. 哪些非基础卖点或具体领先档位支撑这些价值；
3. 这些整组价值是否已经反映在相对价格和销量表现上；
4. 哪些投入应保护、改善、维持、停止跟进或调整；
5. 产品经理追求溢价、销量或产品线分工时应改变什么。

画像保存事实、过程、结论、边界、版本和证据。报告与问答只消费画像，不重算竞品、量价、卖点分类或行动结论。

## 3. 权威输入修订

### 3.1 正式竞品唯一来源

正式生成必须读取当前 `published + current` 的竞品画像 `competitor_profile_agent_snapshot_v2`：

- 使用画像保存的完整实际候选集合，不重新召回；
- 使用画像保存的候选原始顺序、逐款多维分析、角色、业务得分和 Top 3；
- Top 3 只表示优先分析对象，不截断其余候选；
- 每个候选保留竞品画像版本、pair result hash 和证据引用；
- 正式路径不静默回退旧 M12/M13/M14；
- 预览路径只能显式指定一个竞品画像草稿版本。

竞品画像当前已覆盖 TV 377、AC 155，V5.1 不重跑 M03B—M12D，不修改旧 M12/M13/M14，也不现场执行竞品分析。

### 3.2 分析参考池仍独立存在

正式竞品和分析参考不是一个集合：

- 正式竞品：来自竞品画像，用于替代、分流、升档、同品牌梯度、价值替代等竞争判断；
- 市场参考：来自既有市场、参数、价值战场与合成对照数据，用于参数分组、同预算市场、卖得好/卖得差组合、相邻战场和市场基线。

同一产品可以同时具有两种身份，但必须保存各自来源和用于回答的问题，不能把市场参考冒充直接竞品。

## 4. 低门槛原则

### 4.1 门槛约束的是结论强度，不是是否继续分析

V5.1 不再设置“候选必须整体合格后才能参与所有问题”的总门槛。每个问题只校验自己直接需要的事实：

| 问题 | 最低可用证据 | 可输出结果 |
| --- | --- | --- |
| 相对价格和销量 | 本品与至少 1 个合法竞品/参考组有有效均价和周均销量 | 市场量价差及方向 |
| 同类价值谁兑现更好 | 双方至少有 1 个共同价值/采购理由锚点，且本品或对方有兑现证据 | 相对兑现优势、短板或相当 |
| 参数差异是否值得关注 | 双方存在已知且不同的归一化参数/配置 | 配置差异及关联量价表现 |
| 哪些投入是基础能力 | 至少能形成合法 known 样本的能力事实 | 普及率；样本不足时仅不分类 |
| 哪些竞品配置不用跟 | 对方具备、本品不具备，且本品现有价值与量价未显示受损 | 当前无跟进必要的方向性结论 |
| 哪些投入尚未转化 | 本品确认具备投入，但对应用户价值未成立或弱于对照 | 投入转化短板 |
| 是否存在严格 WTP | 严格方法自己的完整门槛通过 | 严格市场隐含 WTP |

某一维度缺失只把该问题标成 `no_conclusion`；不得把候选整体淘汰，不得传播到其他问题。

### 4.2 直接市场比较采用尽量低的可用门槛

- 1 个合法对照即可形成方向性市场比较；
- 2—4 个对照形成小组比较；5 个及以上形成组级比较；
- 比较周平均价格和周平均销量，不要求共同周度或共同平台；
- 不要求价格必须先发生变化，也不要求形成共同市场选择曲线；
- 保存样本数、范围、对照身份和敏感性，不因样本少而阻断结论；
- 输出是“这组价值对应的市场量价表现”，不是实验因果或单参数净增量。

### 4.3 参数与配置比较不预设高、中、低档

- 所有不同的归一化参数值均可分组比较；
- 不要求先定义高中低等级；
- 单组只有 1 个 SKU 仍可作为方向性参照；
- HDMI 2.1 等高普及功能不能仅因名称不同成为差异卖点；
- 泛能力是基础能力时，具体领先档位仍可单独判断是否形成用户价值。

### 4.4 基础能力门槛不向上游传播

`known >= 5` 且普及率 `>= 80%` 仍可作为确认 `table_stake` 的默认起点，但只用于“确认它是基础能力”：

- known 样本不足：状态为 `not_assessed`，不进入主卖点，也不触发 review；
- 普及率未达阈值：不自动等于差异卖点，继续看具体档位和用户价值；
- missing 不作 false；
- 基础能力判断不阻断价值、量价、投入或 SKU 结论。

### 4.5 严格方法是增强层，不是发布门槛

市场合成对照、平衡性、共同周度、共同平台、留一稳定性、严格金额 WTP 等原门槛继续保留在各自方法内，但：

- 只决定能否输出该增强结果；
- 不阻断直接竞品量价比较；
- 不阻断价值项、SKU 或版本发布；
- 严格结果为 0 时，不在产品经理报告中反复输出“无法计算”。

## 5. 量化结果分层

画像必须区分四层，不把所有量化都压到严格 WTP：

1. `user_value_evidence`：用户价值是否已被感知和兑现；
2. `direct_market_gap`：具备相近价值的竞品/参考组与本品的价格、销量差；这是默认主量化结果；
3. `market_archetype`：卖得好/卖得差的价值组合、同预算组、参数组、相邻战场和市场合成基线；
4. `strict_market_implied_wtp`：严格门槛通过后才输出的市场隐含 WTP 增强结果。

产品经理默认看到第 1—3 层。第 4 层只在成立时补充，不成立时不制造负面版面。

## 6. 状态与复核语义

### 6.1 问题与价值项状态

每个独立问题、量化结果和用户价值项使用：

- `conclusion_available`：直接证据足以形成结论；
- `partial_conclusion`：至少有方向性结论，同时存在明确限制；
- `no_conclusion`：该问题没有直接证据；
- `invalid`：输入跨类目、版本/哈希不一致、结构损坏或计算结果自相矛盾。

`review_required` 是叠加标记，不是第五种分析状态，也不自动禁止已经成立的其他结论。

### 6.2 SKU 状态

- 至少 1 条有效产品经理结论且无结构错误：SKU 可用；
- 只有部分问题可答：SKU `partial_conclusion`，仍可正式消费；
- 所有问题均无直接证据但结构合法：SKU `no_conclusion`，正式返回“数据不足，无结论”；
- 只有结构、隔离、版本、哈希或持久化完整性错误：SKU `invalid`。

未知投入、竞品局部复核、基础能力样本不足、严格 WTP 未通过，不得把 SKU 变成 `invalid`。

### 6.3 版本状态

版本发布质量只检查：

- 权威 SKU 是否完整生成；
- generation failure、跨品类串线、重复 SKU/self pair、悬空引用是否为 0；
- schema、fingerprint、result hash、来源版本是否一致；
- 已保存结论是否存在直接冲突。

存在 `partial_conclusion` 或 `no_conclusion` SKU 时允许版本质量为 `limited`；只有 `invalid` 或完整性错误才为 `blocked`。

## 7. 画像数据合同增量

V5.1 至少新增或明确保存：

- `competitor_profile_version_id`、`competitor_profile_version`、`method_version`；
- 竞品画像完整候选 manifest、Top 3 标签、pair hash 和角色；
- 分析参考池及其问题用途；
- 每个问题的 selected/rejected 候选、最低证据、状态、强度和限制；
- 每个价值项四层量化结果；
- 每个投入的基础能力判断与投入分类，且状态互不传播；
- SKU 结论状态、有效结论数、无结论数、invalid 原因；
- 版本质量的完整性计数和 conclusion distribution；
- input fingerprint 必须绑定竞品画像 version id/result hash。

所有新增持久化字段有 typed schema、migration、repository 回读、result hash 与版本隔离测试。

## 8. 智能体消费边界

- 默认只读取 current published V5.1 画像；
- 内部验收可显式指定一个 draft 版本；
- 报告、卡片、JSON、Markdown 和问答锁定同一画像版本；
- 不现场调用竞品画像分析、M12/M13/M14、量价重算、投入分类或 WTP 计算；
- `no_conclusion` SKU 明确返回“现有数据不足，暂不能形成该 SKU 的用户卖点价值结论”；
- 技术状态、版本、hash、门槛和证据缺口只进入审计/下钻，不进入产品经理首屏。

## 9. 65E7Q 首验标准

在 205 只生成新 draft，并至少满足：

1. 正式竞品来自当前竞品画像，候选 20，Top 3 为 `TV00027801 / TV00028909 / TV00029936`；
2. 竞品候选与 51 款市场参考分开保存，不互相冒充；
3. 竞品画像读取后不再查询旧 M12/M13/M14 形成候选；
4. 当前 5 个用户价值项可继续生成；已有 4 个市场量价比较不能因 linked investment review 被整体禁用；
5. 至少能输出相对价格/销量、相对价值兑现、投入转化和产品角色中的有效结论；
6. 单个投入 `unknown` 只影响该投入；不得使其关联的全部价值项 review；
7. 严格 WTP 为 0 不影响画像、报告或问答使用；
8. 每条量价结论能回溯实际竞品/参考组、样本数和周均量价；
9. 回读 hash、报告、问答与生成结果一致；
10. 不 publish、不切 current。

## 10. TV/AC 完成定义

1. TV 377、AC 155 权威 SKU 均生成 draft，无漏 SKU和跨类目；
2. 正式竞品画像可读率 100%；无法读取的 SKU 只允许成为明确 generation failure，不允许静默回退；
3. `direct_market_gap`、`partial_conclusion`、`no_conclusion`、`invalid` 分布可审计；
4. `invalid`、generation failure、hash mismatch、dangling reference 均为 0；
5. 局部 unknown/review 不再全局传播；
6. 报告和问答只消费画像；
7. 本地综合回归、迁移、性能、方法/工程/业务评审通过；
8. 205 先通过 65E7Q，再通过 AC 单 SKU，最后才允许全量 draft；
9. publish/current 必须由用户另行明确批准。

## 11. 明确不做

- 不重做竞品画像或现场竞品分析；
- 不重跑 M03B—M12D；
- 不修改旧 M12/M13/M14 历史结果；
- 不把市场关联伪装成随机实验因果；
- 不承诺精确单参数净新增销量；
- 不因严格 WTP 不成立而填充负面报告内容；
- 不在本次需求中重做飞书卡片视觉样式；
- 不自动 review、publish 或切 current。
