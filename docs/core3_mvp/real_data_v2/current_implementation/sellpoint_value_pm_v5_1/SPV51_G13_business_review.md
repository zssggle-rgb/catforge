# SPV51-G13 产品经理业务评审

状态：passed_for_single_sku_acceptance

日期：2026-07-17

## 1. 总结论

保存的 V5.1 画像已经能为产品经理提供一笔可行动的“用户卖点价值账”，而不是输出分析过程自证。它能够按逻辑顺序回答：哪些非基础卖点形成了用户价值、哪些投入值得保留、哪些投入没有转化、哪些竞品配置不用跟或需要补、当前价格是否得到市场表现支撑、如果追求销量应改卖点/价格还是 SKU 角色。

## 2. 产品经理看到的逻辑顺序

1. 先看本 SKU 已形成的用户价值与对应非基础卖点；
2. 再看这些投入是继续保留、改善兑现、不用跟、基础维持还是竞争缺口；
3. 再看正式竞品与市场参照分别在哪个问题中被使用，避免逐款无目的比较；
4. 再看周均价格、销量、参数组和市场组合表现，判断当前价格与规模是否匹配；
5. 最后形成产品动作：保留什么、停止堆什么、补什么、价格怎么处理、SKU 承担什么角色。

## 3. 业务语言与展示边界

- 首屏突出“卖点 + 用户价值 + 产品动作”，基础功能不占核心卖点位置；
- 不使用“反事实、门禁、合成控制、linked review”等过程术语作为产品经理结论；
- 版本、hash、状态机和生成时间不进入短答、Markdown 或飞书卡片正文，只保留在结构化审计字段；
- strict WTP/synthetic 未成立时不生成一串负面技术说明；已有直接量价和产品动作继续展示；
- 数据不足时只返回“现有数据不足，暂不能形成该 SKU 的用户卖点价值结论”；数据异常时明确先修数据，不给产品建议。

## 4. 对 65E7Q 的验收含义

G02 已冻结 65E7Q 的业务门禁：20 款正式竞品、Top 3、51 款分析参照、5 个价值项和旧 V5 已有的 4 个直接量价比较。G13 证明新的画像和下游消费合同能够保存并表达这些内容，不会因 strict WTP 为 0 或单个投入 unknown 再把全部结论清空。

本评审只判定“结构和方法具备产品经理使用价值”。65E7Q 实际应该保留哪些投入、价格是否撑得住、销量动作是什么，必须由 SPV51-G15 在 205 生成唯一 draft 后按真实数据验收，不能在本地 fixture 阶段提前写结论。

## 5. 通过标准

- 能从同一保存画像生成报告、卡片数据和问答，三者 result hash 一致；
- 下游没有现场召回竞品或重算量价/WTP；
- 结论可追溯具体候选、问题用途、样本数和周均量价；
- 产品经理可据此做产品定义、投入取舍、价格和 SKU 角色判断；
- 真实 65E7Q 与 AC 业务可用性仍分别由 G15、G16 控制，未通过不得全量生成。
