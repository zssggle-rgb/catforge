# CatForge 竞品画像 V1 方法合同

状态：G03 方法冻结

日期：2026-07-14

适用范围：TV、AC；同一 `project_id`、`category_code`、taxonomy 和 serving scope 内的 SKU pair。

## 1. 方法目标

本合同把竞品识别拆成五个不可合并的阶段：

```text
全品类可用 SKU
  -> 多入口召回 manifest
  -> 关系资格判定
  -> 业务问题可用性
  -> 0—3 款重点竞品选择
```

五个阶段分别回答：

1. 哪些产品有必要进入计算范围；
2. 它与目标 SKU 的哪一种竞争关系真实成立；
3. 它能支持回答哪些产品经理问题；
4. 证据不足时应保留为什么未知，而不是误判为关系不成立；
5. 哪些候选带来独立决策信息，值得进入重点竞品看板。

任何阶段不得用候选数量、总分或展示上限替代下一阶段的业务门槛。

## 2. 强制前置隔离

候选召回前必须同时锁定：

- `project_id`；
- `category_code`；
- 主数据中的 `product_category`；
- SKU 主数据归属或品类前缀；
- 每个输入模块的精确 rule version；
- taxonomy version；
- published/current，或显式指定的 preview version；
- profile version 保存的 serving scope 和 source batch IDs；
- M07 analysis window、analysis population 和市场口径。

任一强制条件冲突时，pair 状态为 `blocked`，记录冲突证据，不进入关系计算。不得使用“同表最新一行”“同 category_code 的所有 current 行”或单个 storage batch 替代上述合同。

## 3. 三个业务集合

### 3.1 召回候选 manifest

命中至少一个召回入口的 SKU 全部进入 manifest。manifest 无业务数量上限，保留每个入口、入口事实、输入版本和召回结果哈希。

进入 manifest 只表示“值得判断”，不表示它已经是竞品。

### 3.2 正式竞品候选

至少一类竞争关系通过资格门槛，并且至少能回答一个正式业务问题的 SKU，进入正式竞品候选集合。

### 3.3 分析参考产品

没有通过正式竞争关系，但能用于市场基线、参数档位、价值组合、高低绩效或相邻战场分析的 SKU，进入独立参考集合。参考产品不得被卡片和报告称为直接竞品，也不得为了凑满重点竞品而升级。

同一 SKU 可以既是正式竞品，又承担一个分析参考用途；两个身份和用途必须分别保存。

## 4. 多入口召回

### 4.1 召回入口

| 入口 | 最低召回条件 | 主要用途 | 不能单独证明 |
| --- | --- | --- | --- |
| 同购买池 | 产品形态兼容，尺寸/能力段可比较，均价处于同预算或相邻预算范围 | 直接、同预算关系 | 用户价值重合 |
| 同品牌梯度 | 同品牌、产品形态兼容，处于目标 SKU 相邻价格/能力梯度或同预算重叠区 | 产品线升级、降级、内部分流 | 产品线角色成立 |
| 降档入口 | 价格低于目标且至少共享一项非通用任务、价值或成交理由 | 低价分流 | 基础价值足够、销量被分流 |
| 升档入口 | 价格高于目标且至少共享一项非通用任务、价值或成交理由 | 上探替代 | 价值更强、用户愿意加价 |
| 场景入口 | 承接相同主要场景/任务，允许尺寸、技术路线或配置不同 | 场景方案替代 | 属于同一购买池 |
| 同价值入口 | 共享非通用用户价值，或共享价值且存在不同表达/兑现结果 | 价值路线比较 | 用户会在两款中二选一 |
| 市场参考入口 | 同一可比市场内可用于参数档位、价值组合或量价基线 | 参照研究 | 正式竞品关系 |

### 4.2 预算和价格方向

V1 的默认召回配置为 `competitor_profile_recall_v1`：

- 同预算：候选均价相对目标均价在 `[-15%, +15%]`；
- 相邻预算：TV/AC 各自品类配置中的相邻价格档，或均价相对差在 `(-30%, -15%)`、`(15%, 30%)`；
- 明确降档：候选均价至少低 `8%`，`15%` 及以上记录为强价格差；
- 明确升档：候选均价至少高 `8%`，`15%` 及以上记录为强价格差；
- 场景可达预算：同预算或相邻预算；超出相邻预算只能进入参考池，除非同品牌梯度或明确场景方案关系另有证据。

阈值用于召回和关系方向，不直接证明价格作用。阈值必须配置化并写入 profile version；调整阈值必须升配置版本，不能原地修改历史画像。

### 4.3 产品形态兼容

产品形态兼容由品类配置决定，不以参数是否相等机械判断：

- TV：优先使用同屏幕尺寸；场景替代允许相邻尺寸，但必须存在相同核心任务和场景证据；
- AC：必须区分挂机、柜机等产品形态，并以适用空间/能力段判断购买可比性；不同形态只有在相同空间任务明确成立时才能进入场景入口；
- 缺失产品形态或关键尺寸/能力段时，不推定兼容，关系进入 `unassessable` 或 `review_required`。

具体品类映射在 G04 的版本化配置合同中落盘；运行代码不得写死 TV 规则后复用于 AC。

### 4.4 去重和完整性

同一 target×candidate 无论命中多少入口，只形成一个 pair manifest，保存全部 `recall_sources`。候选输入顺序、数据库返回顺序和分页方式不得改变 manifest、关系结果或结果哈希。

分页只影响读取方式和展示，不得裁掉业务候选。性能超限时返回明确失败或降级状态，禁止静默截断为 Top 12、Top 20 或其他数量。

## 5. 独立证据族

关系资格只能使用已发布画像事实。为避免同一语义被多模块重复计数，V1 将证据归为五族：

| 证据族 | 权威来源 | 能否独立参与正式关系 |
| --- | --- | --- |
| F1 成交理由 | M12D 已成立核心支付理由、关键价值锚点 | 是 |
| F2 任务与价值场景 | M09C 主/辅任务，M11C 主/辅价值战场，M11D 市场位置 | 是；同一语义 lineage 只算一族 |
| F3 目标人群需求 | M10C 主/辅目标客群及需求特征 | 是 |
| F4 用户兑现与卖点价值 | M05C 用户感知，M12C 可用的卖点价值角色和市场表现 | 是 |
| F5 产品能力与表达 | M03B 参数事实，M04C 卖点表达 | 只能作为支撑；不能单独成立正式竞品 |

同一 source evidence 经多个下游模块映射后仍只算一个独立证据。关系结果必须保存 `evidence_family`、source module/version、record/evidence IDs 和 lineage hash。

### 5.1 通用价值过滤

“画质好”“制冷快”“操作方便”等品类大词、行业基础门槛和覆盖面过高的采购理由，只能作为召回或支撑证据，不能单独成立同价值、直接、升档或降档关系。

通用性由版本化 taxonomy 标记与当前品类覆盖率共同判断：

- taxonomy 标记为 table-stake/generic 的项为通用；
- 在当前 serving scope 中覆盖率达到配置上限的项降为 supporting；
- 只有具体场景、具体好处、具体档位或具体兑现差异，才可作为区分性证据；
- 覆盖率缺失时不得反向认定为区分性证据。

G02 中 65E7Q 共享核心锚点的 309 款候选因此只被召回，不会仅凭共享锚点成为 309 款正式竞品。

### 5.2 门槛功能过滤

在当前品类 serving scope 中普遍具备、只保证产品可以正常进入购买池的功能，归为门槛功能。门槛功能：

- 参与“基础价值是否足够”和产品形态兼容判断；
- 不作为差异化用户价值；
- 不单独触发同价值、直接、升档或配置跟进结论；
- 只有明确领先档位、具体体验兑现或对主要任务形成阻断时，才从门槛事实升级为可比较差异。

例如，普遍具备的 HDMI 2.1、HDR 名称或基础联网能力只保存为兼容性事实；没有具体领先档位和用户价值证据时，不进入重点配置结论。门槛功能的 taxonomy 标记、覆盖率阈值和例外档位必须版本化。

## 6. 购买池资格

购买池不是一个相似度总分，而是四个门槛的组合：

1. 品类与产品形态兼容；
2. 尺寸/能力段对目标任务可替代；
3. 预算对用户可达；
4. 至少一项用户任务或价值场景重合。

购买池分级：

| 级别 | 定义 | 可支持关系 |
| --- | --- | --- |
| P0 | 同形态、同尺寸/能力段、同预算，且核心任务与至少一项区分性用户价值重合 | 直接替代、同预算替代及其他关系 |
| P1 | 同形态、同尺寸/能力段、同预算或相邻预算，核心任务重合，但价值路线存在明显差异 | 同预算、升档、降档、同品牌 |
| P2 | 形态或尺寸/能力段不同，但明确解决同一场景任务，预算可达 | 场景替代 |
| P3 | 只满足市场参考可比性，不足以证明用户会放入同一购买清单 | 同价值研究或 reference only |
| unknown | 任一必要门槛未知，无法确认 | 不得用于直接购买选择结论 |

P0/P1/P2 表示不同购买逻辑，不是从好到差的机械分数。P3 不能被报告写成“用户会二选一”。

## 7. 七类关系资格

每个关系独立产生 `passed`、`limited`、`unassessable`、`failed` 或 `review_required`。一款候选可同时通过多个关系，必须保留主关系与全部辅助关系。

### 7.1 直接替代 `direct_substitute`

必须同时满足：

1. 购买池为 P0；
2. 至少两个独立证据族成立，其中至少一个来自 F1 或 F4；
3. 共享证据中至少一项为区分性用户价值，不只是通用门槛；
4. 双方 M07 市场口径可比；
5. 没有关键产品形态、主任务或核心理由冲突。

M12D 一方为 `weak_expression_only` 时，不用“没有成交理由”替代未知；若 F2/F3/F4 中仍有两个独立证据族，关系最高为 `limited`，不得成为高置信直接替代。

### 7.2 同预算替代 `same_budget_alternative`

必须同时满足：

1. 均价处于同预算范围；
2. 购买池为 P0 或 P1；
3. 双方完成相同主要任务；
4. 双方至少各有一条可识别用户价值路线；
5. 价值路线不同，或者核心理由相同但表达、兑现或配置路径明显不同。

若双方价值路线高度相同且直接替代门槛通过，主关系应为直接替代，同预算替代作为辅助关系。

### 7.3 降档分流 `downtrade_diversion`

必须同时满足：

1. 候选均价至少比目标低 8%；
2. 购买池为 P0/P1，或明确共享目标的主要任务；
3. 候选覆盖目标 SKU 的基础价值底线：至少一个 F1/F2/F4 核心价值证据，加上所需 F5 门槛能力；
4. 不存在已知的任务阻断或关键能力缺失；未知不能当作满足；
5. 候选周均销量不低于目标，或在对应购买池达到品类配置的有效市场承接门槛。

只有低价、只有高销量、只有共享通用功能均不成立降档分流。价格差达到 15% 且周均销量明显更高时，可标记强分流；市场差异只能表述为观察到的分流压力，不能表述为“降价必然增加多少销量”。

### 7.4 升档替代 `uptrade_alternative`

必须同时满足：

1. 候选均价至少比目标高 8%；
2. 购买池为 P0/P1，或与目标共享主要任务和目标人群；
3. 候选在至少两个独立证据族上形成更强价值，其中至少一个来自 F1 或 F4；
4. 更强价值不是单一通用参数或基础功能；
5. M07 存在有效市场承接，不要求候选销量高于目标，但必须能够判断其不是无市场结果的配置样本。

只因价格更高、参数更多或品牌更高端，不成立升档替代。

### 7.5 同品牌梯度 `same_brand_ladder`

必须同时满足：

1. 品牌标准化后相同；
2. 产品形态兼容；
3. 至少满足下列之一：同预算重叠、同形态同尺寸/能力段的相邻价格梯度、同系列角色重叠、共享核心任务且存在明确升级/降级路径；
4. M07 可判断价格和销量位置；
5. 至少一个 F1—F4 证据说明产品线为何会发生升级、降级、重复覆盖或内部分流。

同品牌的全部 66 款产品不能自动成为 65E7Q 的同品牌竞品。相邻梯度按兼容购买池中的价格顺序计算，并保留上下相邻 SKU；其他同品牌产品只在另有正式关系时进入。

### 7.6 场景替代 `scenario_substitute`

必须同时满足：

1. 购买池为 P2，或产品形态不同但明确解决相同主要场景任务；
2. F2 必须成立；
3. F1、F3、F4 中至少再有一个独立证据族成立；
4. 用户预算可达，或者候选代表明确的同场景产品方案切换；
5. 形态、安装、空间或能力段不存在已知阻断。

只有同任务名称、同客群名称或同战场名称，均不足以成立场景替代。

### 7.7 同价值替代 `same_value_substitute`

必须同时满足：

1. 共享至少一项区分性用户价值；
2. 至少两个独立证据族成立，其中 F1 或 F4 必须存在；
3. 能比较该价值的能力、表达、用户兑现或市场承接中至少两层；
4. 双方 M07 市场口径可比；
5. 共享通用锚点、基础卖点或行业门槛不能单独成立。

同价值替代可用于回答卖点价值和价值兑现问题；若购买池仅为 P3，不得据此回答用户会在两款中二选一。

## 8. 关系失败与未知

| 情况 | 处理 |
| --- | --- |
| 必要事实明确不满足 | 对应关系 `failed`，保存失败原因 |
| 必要事实缺失 | 对应关系 `unassessable`，不得写成“不成立” |
| 证据冲突或 lineage 异常 | `review_required`，不驱动确定性结论 |
| 只命中召回入口、无关系可评 | 候选 `recalled_only` |
| 无正式关系但有参考用途 | `reference_only` |
| 至少一个关系通过且问题可用 | 候选 `eligible` 或 `limited` |
| 跨品类、版本、taxonomy 或 serving scope 冲突 | `blocked` |

`failed`、`unassessable` 和 `review_required` 必须分开保存，报告不得把三者合并为“不是竞品”。

## 9. 业务问题可用性

关系成立不表示所有问题都能回答。每个 pair 按问题保存 `eligible`、`limited`、`unavailable` 和原因。

| 业务问题 | 最低关系/数据条件 | 可以回答 | 不允许回答 |
| --- | --- | --- | --- |
| 用户会在谁之间选择 | direct passed，或同预算 passed 且 P0/P1；M07 + 两个独立价值证据族 | 选择取舍、双方核心价值路线 | 实际转化率、因果份额 |
| 当前价格和销量受到谁的压力 | 任一正式关系；双方同口径 M07 | 均价差、周均销量差、市场承接方向 | 降价必然新增多少销量 |
| 哪项用户价值容易被替代 | direct/same-value/uptrade/downtrade；F1/F4 必须可用 | 覆盖、强化、兑现或绕开哪项价值 | 单卖点因果 WTP |
| 哪些配置需要跟进 | 正式关系 + F5 差异 + F1/F2/F4 用户价值或市场压力 | 配置差异是否改变竞争 | 竞品有而本品没有就必须跟 |
| 同品牌产品线是否互相分流 | same-brand passed；M07 + 产品线价值差异 | 升级、降级、重复覆盖、角色空档 | 只凭同品牌下结论 |
| 是否存在另一种场景方案 | scenario passed；F2 + 另一独立证据族 | 哪种方案解决同一场景 | 跨场景强行替代 |
| 上探或下探应该防谁 | uptrade/downtrade passed；M07 + 对应价值门槛 | 价格梯度和价值路线压力 | 把市场关联写成因果增量 |
| 是否进入重点竞品 | 候选 eligible，或 limited 且重点选择所需问题为 eligible；置信度中及以上 | 是否带来独立决策信息 | 用总分机械补足三款 |

M04C、M05C、M09C、M10C、M11C、M11D、M12C 的缺失只关闭依赖该事实的问题。M03B、M07 或产品主数据的硬门槛缺失时，依赖购买可比性的关系不可评。

## 10. 量价比较合同

### 10.1 主口径

双方基础量价比较固定消费相同 M07 analysis window、analysis population 和市场口径中的：

- 加权均价；
- 周均销量；
- 总销量、销额和活跃周仅作解释字段；
- 价格档、尺寸/能力档和市场百分位。

计算并保存：

- `price_gap = candidate_price - target_price`；
- `price_gap_pct = candidate_price / target_price - 1`；
- `weekly_volume_gap = candidate_weekly_volume - target_weekly_volume`；
- `weekly_volume_ratio = candidate_weekly_volume / target_weekly_volume`；
- 双方在可比购买池中的价格和周均销量百分位。

分母为 0、价格/销量缺失或口径不一致时结果为 unknown，禁止填 0。

### 10.2 共同周和平台

共同在售周、共同平台、促销期和价格波动用于补充诊断和置信度说明，不作为候选召回、正式关系或基础量价比较的硬门槛。

### 10.3 可输出的市场判断

| 观察组合 | 允许的业务判断 |
| --- | --- |
| 更低价格 + 更高周均销量 + 基础价值足够 | 低价产品形成规模分流压力 |
| 同预算 + 更高周均销量 + 更强/不同价值路线 | 同预算竞争路线获得更强市场承接 |
| 更高价格 + 更强用户价值 + 有效销量 | 升档价值获得市场承接，占据上探空间 |
| 目标价格更高 + 用户价值兑现更强 + 销量不弱 | 目标当前溢价获得相对市场支撑 |
| 价格更低但销量也更低 | 不能得出降价会提升销量；只保留价格差事实 |
| 参数更多但价值/销量不强 | 不构成必须跟进的配置依据 |

所有判断均是同口径市场比较，不自动升级为单卖点因果增量、严格 WTP 或“去掉卖点会损失多少销量”。技术 DTO 固定保存 `causal_claim=false`；产品经理报告用直接业务语言表达市场事实，不展示方法免责声明堆砌。

## 11. 分析参考用途

正式竞品候选之外，允许保存以下 reference purpose：

1. `market_baseline_without_value`：用于构造“没有该组用户价值”的市场基线；
2. `high_performance_value_bundle`：同一可比市场中销量承接较好的价值组合；
3. `low_performance_value_bundle`：同一可比市场中销量承接较弱的价值组合；
4. `parameter_tier_reference`：对所有已知不同参数档位进行量价比较，不预设高/中/低结论；
5. `adjacent_battlefield_reference`：用于判断增强已有战场或满足什么条件进入新战场；
6. `same_value_realization_reference`：同一价值下表达或用户兑现不同的产品；
7. `price_volume_archetype_reference`：同价格/销量组合的市场原型。

reference purpose 只定义可用参照，具体市场合成、卖点价值量化和战场机会由用户卖点价值画像消费后完成。竞品画像不得把 reference 直接改写为用户选择关系。

“没有该组用户价值”的 donor 只能使用明确 absence、lower tier 或不承接该价值且证据完整的产品；unknown、缺画像和弱表达不能当作“没有”。高低绩效组合只能在相同市场口径并控制价格/产品形态等基础差异后由下游方法使用，竞品画像本身不输出组合因果结论。

## 12. 置信度、证据和复核

### 12.1 关系置信度

置信度不用于掩盖硬门槛失败：

- `high`：所有硬门槛已知，至少三个独立证据族成立，包含 F1/F4，无 blocking/conflict；
- `medium`：所有硬门槛已知，至少两个独立证据族成立，满足对应关系的必需证据，无 blocking；
- `low`：只有一个独立证据族、关键证据弱或存在可解释冲突；进入 `review_required`，不自动驱动重点结论；
- `unknown`：必要事实不足，关系 `unassessable`。

关系可以通过但只对部分问题为 `limited`。候选整体状态由其最强可用关系和问题覆盖决定，不使用平均分掩盖缺失。

### 12.2 必存证据

每条关系至少保存：

- 通过、失败、未知和复核原因代码；
- 购买池级别与每个门槛结果；
- 成立的独立证据族及其业务摘要；
- source module、profile/rule/taxonomy version；
- source record IDs、evidence IDs、lineage hashes；
- 量价原值、差值、口径和缺失原因；
- 关系置信度、review status、limitations；
- 方法配置版本和 pair result hash。

### 12.3 必须进入复核的情形

- 关键证据族相互冲突；
- M03B 或其他上游出现品类/rule/taxonomy 串线；
- 产品形态、尺寸/能力段标准化不确定；
- 通用价值覆盖率处于配置边界；
- 关系仅由弱表达、claim-only 或低置信映射支撑；
- 同品牌梯度无法确定相邻位置；
- 量价口径不一致却存在强竞争结论候选；
- 旧画像与新画像重点结论发生无法解释的反转。

## 13. 0—3 款重点竞品选择

重点选择不是总分 Top 3，而是选择能改变不同产品决策的最小集合。

### 13.1 入选门槛

候选必须：

1. 整体状态为 `eligible`，或为 `limited` 且重点选择所需问题明确 eligible；
2. 至少一条关系置信度为 medium/high；
3. 能提供一个已证实的决策主题；
4. 不是 `review_required`、`blocked`、`recalled_only` 或纯 `reference_only`；
5. 与已选候选相比具有新的业务信息，或在同一主题上形成明显更强、证据更完整的压力。

### 13.2 决策主题

按以下顺序寻找信息，不强制每个主题都有候选：

1. `purchase_choice`：谁最可能与本品二选一；
2. `price_scale_pressure`：谁在同预算、低价分流或上探空间上最影响本品；
3. `portfolio_or_scenario`：谁揭示同品牌角色冲突或另一种场景方案；
4. `value_route`：谁证明本品某项用户价值容易被替代，或竞品用另一条价值路线胜出。

同一候选可以覆盖多个主题，但只占一个重点位置。后续候选必须带来尚未覆盖的主题；如果没有新增决策价值，重点列表允许只有 0、1 或 2 款。

### 13.3 主题内确定性排序

主题内采用逐级比较，不做跨主题总分相加：

1. 关系是否完整通过；
2. 关系置信度 high 优先于 medium；
3. 独立证据族更多、F1/F4 更完整者优先；
4. 对应业务问题的量价压力更明确者优先；
5. 证据冲突和 limitations 更少者优先；
6. 若仍相同，按规范化候选 SKU code 稳定排序。

直接替代不满足时，重点列表不强行找一款产品贴“直接竞品”标签。三个位置均不满足入选门槛时，返回“当前数据未识别出需要重点防守的竞品”，同时保留完整候选与 reference 画像供问答和复核。

### 13.4 入选和未入选解释

每个入选候选必须保存：

- 解决的决策主题；
- 主关系、辅助关系；
- 为什么它能改变产品决策；
- 相对目标的用户价值与量价事实；
- 为什么不是其他候选。

每个通过关系但未入选的候选必须保存一个主要原因，例如：决策主题已被证据更强候选覆盖、只重复同类压力、量价证据较弱、只适合专项问答。不得仅保存“rank > 3”。

## 15. G03 方法验收条款

- MP01：召回、正式关系、问题可用性和重点选择四层已分离；
- MP02：候选宇宙无固定业务数量上限，分页不改变集合；
- MP03：七个召回入口与正式关系门槛分离；
- MP04：通用锚点和基础功能不能单独成立竞品；
- MP05：直接替代要求 P0 与至少两个独立证据族；
- MP06：降档要求低价、基础价值和有效市场承接；
- MP07：升档要求更强用户价值和有效市场承接；
- MP08：同品牌只保留相邻或明确重叠梯度，不把全部同品牌 SKU 当竞品；
- MP09：场景替代要求 F2 和另一独立证据族；
- MP10：同价值替代要求 F1/F4 和至少两层可比较事实；
- MP11：缺失为 unassessable，不等于 failed；
- MP12：每个 pair 保存问题级可用性；
- MP13：均价和周均销量为主口径，共同周/平台仅作诊断；
- MP14：市场关联不升级为因果销量、单卖点 WTP；
- MP15：reference purpose 与正式竞品身份分离；
- MP16：重点竞品按独立决策主题选 0—3 款，不机械 TopN；
- MP17：关系置信度、证据 lineage 和 review 规则完整；
- MP18：TV/AC 产品形态规则配置化，不能互相套用；
- MP19：精确 rule/taxonomy/serving scope 隔离写入前置门禁；
- MP20：相同输入和配置生成确定性结果。
