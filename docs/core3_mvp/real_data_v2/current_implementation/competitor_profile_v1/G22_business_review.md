# G22 产品经理业务评审

状态：业务结构通过；真实 SKU 结论待 G24/G25 验收

日期：2026-07-14

## 1. 这个画像给产品经理的核心帮助

它把分散的参数、卖点、采购理由、用户价值和市场量价，整理成一笔产品经理能直接用于 SKU 决策的“竞争选择账”：用户会拿本品和谁比较，比较时看重什么，本品在哪些价值上更有理由被选，当前价格和销量是否得到这些价值支撑，以及下一版是该保留投入、补价值、调价格，还是调整 SKU 在产品线中的角色。

## 2. 产品经理最终应按这个顺序得到答案

1. 先回答“真正影响本品决策的是谁”：0—3 款重点竞品，每款承担不同问题；没有足够证据时不凑数。
2. 再回答“用户为什么会在这些产品之间选择”：同购买池、同预算、升降档、场景、同价值或同品牌梯度分别说明，不用“参数相似”代替选择理由。
3. 再回答“本品的卖点形成了什么用户价值差异”：基础功能只作配置说明；只有具体档位、具体场景、具体好处或用户兑现差异才进入主结论。
4. 再回答“这些价值是否得到市场表现支持”：展示本品与可比产品的均价、周均销量、价值覆盖和压力方向，明确是市场关联，不把它包装成单卖点因果。
5. 最后回答“产品经理该做什么”：哪些投入继续保留、哪些投入没有转成用户价值、哪些竞品配置不用跟、要销量时优先改卖点/价格/SKU 角色中的哪一个。

## 3. 输出语言要求

- 首屏先给 3—5 条与后文章节一一对应的业务结论，不写系统过程、版本 hash 或“门禁通过”。
- 每条结论必须带产品对象、价值差异、市场表现和建议动作；不能只说“用户认可整机体验”这类适用于所有 SKU 的口水结论。
- “reference only”“counterfactual”“relation status”等内部词只在证据报告出现；业务报告改写为“同预算用户还会看谁”“更便宜但销量更高的产品说明什么”“同一价值还有什么实现路线”。
- 数据不足只影响相应问题，不把整份报告写成负面自证；没有结论的栏目不占首屏。

## 4. 业务边界

本画像能给出有证据的市场比较和产品决策建议，但当前不直接输出单卖点 WTP、单卖点净新增销量或因果价格弹性。若本品价值兑现更好且同时有更高均价/销量，可表述为“该价值组合获得了更好的市场表现支撑”，不能写成“该卖点造成了全部价差/销量”。

## 5. 本次评审未做的事

G22 没有在 205 生成 65E7Q 或 AC 画像，因此不伪造任何 SKU 业务亮点。G24 必须拿 65E7Q 的真实 draft 检查：重点竞品是否合理、短板是否具体、量价比较是否能指导价格/卖点/SKU 角色、卡片与两份报告是否只消费同一画像。只有该验收通过，才进入 AC 和全量。
