# CatForge 竞品画像 V1 需求

状态：G01 业务定义冻结

日期：2026-07-14

## 1. 产品目标

竞品画像 V1 将现有竞品分析智能体在每次问答中临时执行的候选召回、SKU pair 比较和重点竞品选择，提升为可版本化、可审核、可发布、可复用的 CatForge 工厂资产。

它必须稳定回答：

1. 哪些产品会进入用户购买目标 SKU 时的实际比较范围；
2. 每款候选通过价格、用户价值、配置、品牌梯度或使用场景中的哪一种关系影响本品；
3. 本品当前最需要关注哪些重点竞品；
4. 本品在哪些用户价值上占优，哪些价值容易被替代；
5. 哪些竞品配置需要跟进，哪些配置不需要跟进；
6. 当前结论由哪些已发布画像和市场事实支持，哪些部分仍然未知或需要复核。

竞品画像负责计算和保存结论。竞品分析智能体、飞书卡片、产品经理对比报告、分析佐证报告、深入问答和用户卖点价值画像只消费竞品画像，不得在展示或问答阶段重新召回、评分、选择或更换画像版本。

## 2. 当前问题

当前存在三套口径：

1. 旧 M12/M13/M14 依赖 M08、旧 M11 和 M11.7，205 只覆盖 84 款 TV，AC 没有结果；
2. `competitor-set` 基于新版画像现场召回和比较，默认候选存在技术数量限制，结果主要停留在单次问答；
3. 用户卖点价值画像仍把旧 M12/M13 当作正式竞品权威源，同时又从新版市场画像构建分析参考池。

结果是同一个 SKU 可能同时存在“有竞品分析结果”“正式竞品宇宙不可用”和“存在大量市场参考产品”三种互相割裂的状态。

V1 的目标是形成唯一竞品业务事实源，而不是在旧链旁再增加第四套临时判断。

## 3. 画像定位

### 3.1 竞品画像是关系资产

竞品不是候选 SKU 自身的固定标签。一款产品可能是 SKU A 的直接替代品，却只是 SKU B 的升档标杆。因此竞品画像必须同时包含：

- 目标 SKU 级竞争决策画像；
- 目标 SKU × 候选 SKU 的竞品关系画像；
- 该目标 SKU 的完整候选宇宙；
- 0—3 款重点竞品及其入选、未入选和空缺原因。

### 3.2 画像与报告分离

画像保存完整业务事实、关系、证据、限制、版本和审核状态。产品经理卡片和报告只展示能够改变产品决策的结论，不展示内部状态码、表名、规则名、哈希、样本门禁或算法过程。

### 3.3 工厂边界

竞品画像属于 CatForge 工厂资产。运行时导出不得包含 prompt、Gold Set、候选生成模板、内部阈值调参方法或跨品类迁移工具。

## 4. 权威输入

竞品画像 V1 只消费同品类、同项目中已经发布或明确指定用于预览的版本化资产：

| 输入 | 作用 |
| --- | --- |
| M03B 参数事实画像 | 产品能力、具体参数档位和已知/未知状态 |
| M04C 卖点事实画像 | 产品表达的卖点及参数支撑 |
| M05C 用户反馈画像 | 用户感知、正负向体验和未覆盖状态 |
| M07 市场画像 | 均价、周均销量、销额、尺寸档和价格位置 |
| M09C 用户任务画像 | 产品承接的主、辅、机会和不足任务 |
| M10C 目标客群画像 | 产品更容易吸引的需求特征人群 |
| M11C 价值战场画像 | 主、辅、机会和拖后腿价值战场 |
| M11D 语义市场图谱 | 战场、任务、客群的市场空间和 SKU 分布 |
| M12C 卖点价值量化 | 卖点价值角色、市场量价差和竞品拦截证据 |
| M12D SKU 成交理由画像 | 核心支付理由、关键价值锚点和购买阻力 |

竞品画像不得依赖旧 M08、旧 M11、M11.6、M11.7 才能覆盖目标 SKU，也不得把旧 M12/M13/M14 的结果与新版画像结果混算成同一个正式版本。

旧 M12/M13/M14 在迁移期间保持只读，可用于影子对照和回退，不作为新画像生产的必需输入。

## 5. 核心业务概念

### 5.1 竞品候选宇宙

竞品候选宇宙是用户购买目标 SKU 时，可能用于替代、比较、升档、降档、同品牌转移或场景切换的全部产品。

候选宇宙：

- 不设置 3、12、20 或其他业务数量上限；
- 不等于全部同尺寸产品；
- 不因品牌相同而排除；
- 不因某个维度缺失而直接删除；
- 必须保存每个候选进入宇宙的来源和理由；
- 性能限制不得改变候选业务集合。

### 5.2 正式竞品候选

正式竞品候选至少满足一种可解释竞争关系，并且能够用于至少一个正式业务问题。尺寸、价格、品牌或参数相似只能作为关系证据，不能单独证明正式竞争关系。

### 5.3 分析参考产品

分析参考产品不一定进入用户购买替代范围，只用于参数档位、相邻战场、高低绩效组合或市场基线研究。

正式竞品候选与分析参考产品必须分开保存。报告不得把参考产品写成直接竞品，画像也不得为了填充重点竞品而把参考产品升级为正式竞品。

### 5.4 重点竞品

重点竞品是当前最可能改变用户对目标 SKU 价值判断，或者最值得产品经理在产品定义、定价和竞争防守中关注的 0—3 款产品。

重点竞品是完整候选宇宙上的展示和决策标签，不得反向截断候选宇宙。重点竞品不足 3 款时允许为空，不强行补弱候选。

## 6. 允许的竞品关系

一款候选可以同时具备多个关系，画像必须保留全部成立关系，并标记主关系和辅助关系。

| 关系 | 业务定义 | 主要回答的问题 |
| --- | --- | --- |
| 直接替代 | 与本品处于同一购买池，并在核心采购理由、主价值战场和预算上高度重合 | 用户为什么会在两款之间二选一 |
| 同预算替代 | 预算接近，用户价值路线不同但都能完成主要购买任务 | 同样预算下用户会怎么取舍 |
| 降档分流 | 价格更低且基础用户价值足够，能够带走部分目标用户 | 本品销量是否受到低价产品分流 |
| 升档替代 | 价格更高但用户价值更强，能够吸引用户继续加价 | 本品上探空间被谁占据 |
| 同品牌梯度 | 同品牌内部存在升级、降级、重复覆盖或相互分流 | 产品线角色是否清晰 |
| 场景替代 | 尺寸、配置或技术路线不同，但解决相同使用场景和用户任务 | 用户是否会用另一种产品方案解决同一问题 |
| 同价值替代 | 双方承接同一用户价值，可比较表达、兑现和市场承接差异 | 本品的用户价值是否真正领先 |

只有价格接近、参数相似、品牌相同、尺寸相同或销量较高，均不足以单独成立上述关系。

## 7. 候选状态与问题级可用性

每个候选必须保存独立状态：

- `eligible`：至少能用于一个正式业务问题；
- `limited`：只能用于部分问题，必须保存可用范围；
- `review_required`：保留在画像和审核队列，不驱动确定结论；
- `blocked`：仅用于审计，不参与业务结论；
- `recalled_only`：已召回但关系评价尚未完成；
- `reference_only`：只属于分析参考池，不属于正式竞品候选。

候选必须按问题记录可用性，至少包括：

- 重点竞品选择；
- 价格与销量压力；
- 用户价值替代；
- 配置跟进判断；
- 同品牌产品线角色；
- 场景替代；
- 升档或降档判断。

低置信候选不得隐藏，也不得与有效候选混算。缺失、空值和未知不得解释为产品不具备、用户不认可或关系不成立。

## 8. SKU×SKU 竞品关系画像

每个目标 SKU × 候选 SKU 必须形成一份可独立查询的关系画像，至少保存：

1. 候选进入宇宙的全部来源和理由；
2. 同一购买池判断及其边界；
3. 价值战场、用户任务和目标客群的主辅重合；
4. 核心采购理由和关键价值锚点的覆盖、强化、替代或绕开；
5. 参数事实、卖点表达和用户感知的共同点与差异；
6. 均价、周均销量、销额和市场位置的差异；
7. 成立的主关系、辅助关系和不成立关系；
8. 对目标 SKU 的压力来源和可能业务影响；
9. 可用于哪些产品问题、不可用于哪些产品问题；
10. 证据、置信度、审核状态、限制和结果哈希。

量价主比较使用已发布 M07 中同一市场口径的均价和周均销量。重叠在售周、共同平台和促销周期可以作为补充诊断，但不得作为候选进入和基础量价比较的硬门槛。

销量和价格差只能支持市场关系与压力判断，不得自动表述为某个卖点的因果销量增量或单卖点 WTP。

## 9. SKU 竞争决策画像

目标 SKU 主画像必须保存：

- 完整候选宇宙数量和各状态分布；
- 正式竞品、分析参考和重点竞品的分离结果；
- 0—3 款重点竞品及其主关系、辅助关系和选择理由；
- 未入选候选的业务原因和空缺原因；
- 本品主要竞争优势；
- 容易被替代的用户价值；
- 价格与销量压力；
- 同品牌产品线关系；
- 需要跟进和不需要跟进的配置依据；
- 证据边界、画像置信度和审核状态；
- 上游版本、输入指纹和结果哈希。

画像中的“配置需要跟进”必须同时有真实竞品关系和用户价值或市场压力证据；竞品具备、本品不具备本身不足以要求跟进。

## 10. 重点竞品选择

重点竞品选择必须满足：

1. 只从 `eligible` 或满足指定问题条件的 `limited` 正式候选中选择；
2. `review_required`、`blocked`、`recalled_only` 和 `reference_only` 不得自动入选；
3. 首选直接竞品优先回答谁最可能与本品二选一；
4. 其余重点位置用于补充价格/销量分流、升档替代、同品牌梯度、场景替代或其他具有独立决策价值的压力；
5. 同一候选可以拥有多个关系，但重点竞品列表不得重复；
6. 重点选择关注业务信息增量，不按一个总分机械取前三；
7. 不足 3 款时保留真实数量，不输出没有决策意义的空结论。

## 11. 画像消费者

### 11.1 竞品分析智能体

正式模式只读取 current published 竞品画像。开发预览必须显式指定 draft profile version，且不得冒充正式结论。

智能体负责：

- SKU 解析；
- 读取画像；
- 生成重点竞品卡片；
- 生成产品经理用户选择对比报告；
- 生成竞品识别与分析依据报告；
- 围绕同一画像版本深入问答。

智能体不得现场改变候选宇宙、重新计算关系、重排重点竞品或从原始数据补结论。

### 11.2 用户卖点价值画像

竞品画像正式发布并完成切换后，用户卖点价值画像必须只读取：

- 完整正式竞品候选；
- 问题级可用候选；
- 同价值、同预算、降档、升档和同品牌关系；
- pair 级量价和价值替代事实；
- 重点竞品标签。

不得继续混用旧 M12/M13/M14、`competitor_set_fallback` 和临时市场候选作为正式竞品。分析参考池继续独立存在。

### 11.3 卡片、报告和问答

卡片、两份报告和问答必须锁定同一个 profile version。展示层只能组织业务语言和选择展示字段，不得重新推导业务结论。

## 12. 版本、审核和发布

竞品画像必须支持：

- `draft`、`review`、`published`、`deprecated` 生命周期；
- version 级和 SKU 级质量状态；
- 同一输入幂等；
- 新草稿不覆盖旧 published；
- published 版本不得原地改写；
- current 切换为独立操作；
- 上游版本变化后的 stale 判断；
- 画像版本 diff；
- TV/AC、project、batch 和 taxonomy 隔离；
- 失败 SKU 隔离和批量续跑。

本任务链只授权生成和验收 draft。任何 published/current 切换必须另行获得用户明确批准。

## 13. 确定性与安全要求

- 画像生产不得依赖外部 LLM 才能通过测试或重复生成相同结果；
- 候选输入顺序变化不得改变结果哈希；
- 不得逐候选 N+1 查询完整上游；
- 评论原文和重证据按问题延迟加载；
- 低置信结论进入审核队列，不得隐藏；
- 跨品类候选必须阻断；
- 导出不得泄露内部 prompt、Gold Set 或规则模板；
- 正式报告不得展示 snake_case、模块编号、表名、哈希或技术门禁。

## 14. 迁移与退役边界

1. 新画像开发期间，旧 M12/M13/M14 和当前竞品智能体保持可回退；
2. 新画像使用独立表和独立 profile version，不覆盖旧表；
3. 先在 65E7Q 生成草稿并验收完整候选、关系画像、卡片、两份报告、问答和用户卖点价值画像消费；
4. 65E7Q 通过后再做 AC 单 SKU 品类隔离验收；
5. TV/AC 单 SKU 均通过后才允许生成全量草稿；
6. 全量草稿复核后单独决定是否发布；
7. 只有新竞品画像正式发布、所有消费者完成切换并通过回退演练后，旧 M12/M13/M14 才能进入退役评估；
8. 退役不是删除历史数据，历史结果必须继续可审计回读。

## 15. G01 验收条款

- CP01：画像被定义为目标 SKU 级决策资产和 SKU×SKU 关系资产，而非候选自身标签；
- CP02：候选宇宙无固定业务数量上限；
- CP03：正式竞品和分析参考分开保存；
- CP04：七类竞争关系边界明确，并允许一款候选保留多个已成立关系；
- CP05：候选状态和问题级可用性分离；
- CP06：重点竞品为 0—3 款展示标签，不截断完整候选；
- CP07：新版全量画像是权威输入，旧 M08—M14 不是必需依赖；
- CP08：均价和周均销量是基础量价口径，共同周和平台不作硬门槛；
- CP09：价格销量差不自动升级为单卖点因果增量或 WTP；
- CP10：竞品分析智能体只消费画像，不现场重算；
- CP11：用户卖点价值画像只消费正式竞品画像，分析参考池保持独立；
- CP12：卡片、两份报告和问答锁定同一画像版本；
- CP13：draft、review、published、deprecated 和 current 边界明确；
- CP14：published 不得原地改写，正式切换必须另行批准；
- CP15：TV/AC、project、batch 和 taxonomy 隔离；
- CP16：65E7Q、AC 单 SKU、全量草稿按顺序设置硬门禁；
- CP17：旧 M12/M13/M14 在新链正式切换前保持回退，不与新画像混算；
- CP18：缺失保持 unknown，低置信进入审核，不隐藏；
- CP19：画像生成确定、可追溯、无外部 LLM 测试依赖；
- CP20：报告只消费业务 DTO，不泄露工厂内部生成方法。
