## 1. 调度原则

1. 任意时刻只允许一个 active Goal；后续 Goal 只能在前置 Goal complete 后创建。
2. 每个 Goal 使用 Goal 模式，不设置 token budget。
3. 当前线程使用一个 10 分钟 heartbeat，只推进当前 active Goal。
4. heartbeat 不得并发启动数据库写入、部署或批量生成任务。
5. 每个 Goal 只暂存自己产生的精确文件，禁止 `git add .`。
6. 用户未跟踪文件、其他任务产物和既有工作树修改全部保留。
7. 205 数据库写入只在对应 Goal 的前置门禁通过后执行。
8. 65E7Q 未通过时禁止 AC 和全量草稿；AC 未通过时禁止全量草稿。
9. 全量生成只写 draft；任何 publish/current 切换需要另行明确授权。
10. 同一阻塞连续三次且无法继续时才标记 blocked。

## 3. G01 允许与禁止

允许：

- 新增 `competitor_profile_v1/` 需求、调度和回执文档；
- 只读引用旧 M12/M13/M14、现有竞品智能体和用户卖点价值画像设计；
- 检查文档一致性和工作树状态。

禁止：

- 修改运行代码、测试、migration；
- 写入 205 数据库；
- 部署或切换发布状态；
- 修改旧 M12/M13/M14；
- 暂存或提交其他任务文件。

关闭条件：

1. 业务需求覆盖 CP01—CP20；
2. 需求和调度文档中的候选、关系、重点竞品、发布边界一致；
3. 明确当前竞品智能体不是正式画像权威源；
4. 明确新画像发布前旧链保持回退；
5. 形成 G01 完成回执；
6. 文档检查通过后才允许创建 G02。

## 4. 后续 Goal 通用关闭模板

每个 Goal 必须记录：

- 允许修改的精确文件；

- 测试和验证证据；
- 数据库、部署和发布动作；
- 未解决问题和边界；
- 下一 Goal 的准入判断。

任何 Goal 不得用“后续再补”关闭其自身必需验收项。
