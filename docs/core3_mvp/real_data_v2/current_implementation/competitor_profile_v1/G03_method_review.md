状态：passed

## 1. 复核结论

G03 方法合同通过，允许进入 G04 详细设计。

本轮没有沿用当前 `competitor-set` 的“先按同尺寸价格排序取固定 limit，再对候选逐个计算和展示 Top 3”方法。新方法保留了当前系统中购买池、采购理由可替代、量价压力和角色多样性四类有效思想，但将它们改造成可版本化画像的分阶段合同：

1. 无固定数量的多入口召回；
2. 七类关系分别通过硬门槛；
3. 按产品问题决定 pair 是否可用；
4. 按独立决策信息选 0—3 款重点竞品。

这解决了 G02 暴露的两个主要风险：共享采购理由会召回过多候选；同品牌或同市场池命中会被错误当成正式竞品。

## 2. 已复核的现有实现模式

| 现有模式 | 保留内容 | 不沿用内容 |
| --- | --- | --- |
| `sop_orchestrators.competitor_set` | 购买池、语义、参数、销量和 M12D pair 证据组合 | `limit` 截断候选、逐候选 N+1、问答时现场重算 |
| `replacement_pressure.py` | 价值替代、价格压制、配置、场景、降档和升档的多角色思想 | 用一个总分决定强压力和主角色 |
| `anchor_substitutability.py` | 核心锚点覆盖、证据强弱、用户兑现和市场验证分层 | 共享通用锚点可直接推高 pair 分数 |
| `sellpoint_value_profile_candidate_service.py` | 完整 manifest、candidate/reference 分离、问题级可用性、确定性排序 | 依赖旧 M12/M13/M14 component 才能 eligible |
| V5 卖点价值方法合同 | broad→eligible、unknown 不当 absence、市场合成 reference 边界 | 共同周/平台作为基础竞品量价比较硬门槛 |

## 5. G04 必须落地的合同

G04 只能把 G03 转成 typed schema、配置、表和状态机，不得重新改变业务方法。必须特别落实：

1. 版本化品类兼容矩阵和阈值配置；
2. 五个独立证据族与 lineage 去重；
3. 七类关系各自的 gate result；
4. relation 状态与 candidate 状态分离；
5. question eligibility 的 typed enum；
6. candidate/reference 双集合和 reference purpose；
7. pair 量价 DTO 与 `causal_claim=false`；
8. 重点竞品决策主题、入选与未入选原因；
9. exact rule/taxonomy/serving scope 读取合同；
10. draft/review/published/current 不可变边界。

## 6. 未阻断边界

- 默认价格阈值来自当前 TV/AC 业务讨论，必须配置化；真实分布回放在 G22/G24/G25 验证，任何调整升配置版本；
- 通用价值和门槛功能覆盖率阈值在 G04 配置中给出，G22 需回放分布，不能在代码中临时调参；
- reference pool 只保存可用参照，不在竞品画像内重复实现卖点价值画像的市场合成算法；
- 本轮未执行生产代码、数据库、部署、重跑、publish 或 current 切换。
