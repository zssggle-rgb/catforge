# GTM 竞价策略助手前端联调

参考稿为 `cankao/终稿/GTM竞价策略助手0916.html`。CatForge Web 的 `/` 和 `/gtm/` 打开每日重点工作，九个业务入口共享侧栏、当前项目、品类、数据范围和证据明细。可直接打开 `/gtm/#/competitor` 等页面。原三竞品研判台入口为 `/core3`，真实数据报告为 `/core3-real-data`，工厂为 `/factory`。

## 后台交付边界

界面采用 React、TypeScript、Vite 和 Semi Design 2.102.0。筛选、表格、弹窗和图标复用与 AdPilot 同版本的 Semi 组件，主蓝与状态色来自默认浅色主题。业务布局以 0916 终稿为基准，旧工厂入口独立按需加载。

浏览器只调用 [GTM OpenAPI](../contracts/gtm-workspace.openapi.yaml)。[TypeScript 类型](../apps/factory-web/src/gtm/contract.ts)与[请求客户端](../apps/factory-web/src/gtm/client.ts)定义前端实际消费的字段。生产构建默认使用同源 `/api/gtm/v1`。如运行端网关路径不同，可在构建时设置 `VITE_GTM_API_BASE`。Vite 和原 Nginx 配置均会剥掉第一层 `/api`，因此上游收到 `/gtm/v1/...`。登录与项目授权由运行端执行。

浏览器有八项接口操作。读取工作区 `GET /context`，查询目录 `GET /projects/{id}/catalog`，读取页面 `GET /projects/{id}/views/{page}`，读会话列表和单个会话，提交附件 `POST .../attachments`，发送消息 `POST .../messages`，提交业务操作 `POST .../actions`。工作区响应声明 `mode=live|sample`。真实接口失败时显示错误和重试。样例服务单独运行，样例没有打入前端包。

下表是页面投影与后台会话拟议数据产品的映射。后台可在投影层组装多份领域结果，前端不负责关联原表或计算经营结论。

| 页面键 | 前端展示与交互 | 后台供给 |
|---|---|---|
| daily | 工作总览和追问、四项核心指标、趋势与渠道分布、重点型号、我品预警与竞品动态、日报文本导出 | 经营表现、巡检、价格观测、上新索引按同一范围汇总。趋势窗口单独标注 |
| key-model | 重点产品明细、型号管理、历史销量/销额/成交均价、来源口径 | `GET /gtm/v1/performance`、运行端重点型号集合 |
| own-monitor | 渠道与预警筛选、门店价格、有效底价、异常明细、证据和处理回执 | `offers/observations`、`inspections`、`alerts/{id}/actions` |

## 请求与状态

- 页面请求传 `category_code`、渠道、细分品类、时间范围、页签与分析对象。主明细表支持关键词、`offset` 和 `limit`，`total` 为过滤后的总数。多选使用重复参数，如 `competitor_ids=tcl65&competitor_ids=mi65`。目录返回稳定 ID 和显示名。细分品类依赖父品类。
- 传 `period=custom` 时，`date_from`、`date_to` 为北京时区含首尾的业务日。实时模式由后台解析相对日期，样例模式的时钟锚点固定为 2026-09-10。刷新重读当前范围。周数据不回填“今日”。
- 响应带版本、项目、品类、快照和业务水位。返回 `ready`、`partial` 或 `unavailable`。部分字段缺源时给 `null` 和原因；真实 0 保留。指标的 `basis` 记录统计总体、粒度、来源批次、覆盖期间、水位。分析快照可携带方法版本、置信度、审核状态。
- 数据表列由 `columns[].key` 对应 `rows[].cells[key]`。数值用 JSON number，单位由列定义给出或写在表头；文本均按纯文本渲染。每行可返回来源、原始行、观测时点和可见证据摘录。来源卖点与用户认可度分别交付，预测数值和收益需要独立证据。
- 操作只能从服务端返回的 `actions` 发起。提交发送项目、页面、作用对象、来源快照和幂等键；操作失败保留输入，成功回执触发重读。读取旧快照、超权限、非法组合等从服务端返回 HTTP 错误。`set-key-models` 输入为逗号分隔型号，后台按本项目解析，歧义应返回 422。`create-report` 创建待确认任务；订阅回执只确认订阅关系。
- 运营上下文和来源版本必须在服务端复核。首页跳转保留公共筛选；由总结发起的新对话附带来源页、页签及快照，后续消息用会话 ID 续接。日报文本导出使用当前快照。其他页面的“导出当前页”仅导出已读取的页内记录。

## 独立样例服务

使用现有项目构建命令生成 `apps/factory-web/dist`，在调试机仓库根目录执行：

```sh
python3 -B tools/gtm-sample/server.py --dist apps/factory-web/dist --port 18166
```

用浏览器打开调试机回环端口的 `/gtm/`。服务也可单独提供 HTTP API；开发前端的 `VITE_PROXY_TARGET` 可指向实际 GTM 后台，若接这个带 `/api` 前缀的样例服务，请使用上述同源静态入口。状态按浏览器会话分开，重启样例服务会重置任务、订阅、对话和已选型号。样例问答由确定性规则生成。

### 可复核的操作

1. 在每日重点工作切换渠道并查询，核对异常数据与明细，点击查看依据并导出日报。切到空调可验证缺源状态。
2. 在重点产品表现选择全渠道、自定义 2026-06-08 至 06-14。65E7Q 周销量为 392 台。改选京东时独立平台口径为 110 台，天猫为 115 台。回到今日应显示日成交缺源。
3. 在竞品洞察选择我品、添加或移除竞品，切换四个页签并查看证据。样例缺少可信单卖点金额和预测销量，此类字段显示为破折号。
4. 打开待办明细，确认完成后刷新；在订阅报告中创建、查看、订阅或取消。新建对话后在最近对话中重开。HTTP 故障、冲突与缺源可分别验收。

底价维护支持提交 CSV/XLSX 并查看导入记录，新建活动进入待确认状态；预警可处理或填写原因忽略。报告任务支持编辑正文、确认发布和订阅。附件、活动、报告和消息的业务字段由运行端复核。样例服务只记录本会话的附件元数据与模拟回执。底价文件解析和启用、正式报告归档、消息投递与实际调价均待后台联调。
